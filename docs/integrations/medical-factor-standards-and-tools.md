# 医学因素术语与行业工具处理方式

核查日期：2026-11-06。本文整理国内病历规范、国际术语体系及行业工具已经公开的处理方式，不涉及本项目的实现建议。关键条款、概念含义和示例结果均在正文说明，链接仅供追溯。外文术语的中文解释为本文概述，不作为官方中文译名。

## 核心结论

已有规范分别解决三个问题：国内《病历书写基本规范》明确哪些发病和症状变化信息需要记录；MeSH、SNOMED CT 区分因素概念及关联、时序、因果关系；Infermedica、DXplain 等工具将患者信息用于候选判断，并展示理由和需要继续确认的信息。相关条款、定义和实例见下文。

## 一、国内依据：病历中已经区分发病诱因和症状加重因素

**文件：**原卫生部《病历书写基本规范》，随卫医政发〔2010〕11号通知印发，落款日期为 2010 年 1 月 22 日。第十八条规定的是住院入院记录的内容，其中第（三）项为现病史。

| 具体位置 | 与本次问题有关的要求 | 含义 |
| --- | --- | --- |
| 第十八条（三）第 1 项：发病情况 | 除起病时间、地点、缓急和前驱症状外，还需记录“可能的原因或诱因”。 | 关注疾病如何开始，以及哪些因素可能与本次发病有关；允许保留“可能”，不要求将推测写成确定病因。 |
| 第十八条（三）第 2 项：主要症状特点及其发展变化情况 | 记录部位、性质、持续时间、程度和演变，并记录“缓解或加剧因素”。 | 关注已有症状在什么条件下减轻或加重，与疾病最初为何发生是不同的记录内容。 |

**这项国内依据说明：发病相关因素与症状变化相关因素应分别记录。**它属于病历书写规范，并非 GB 国家标准或 WS 卫生行业编码标准，也没有提供一套完整的“诱因词库”或自动判定算法。来源：[国家卫健委公布的正式通知及规范全文](https://www.nhc.gov.cn/wjw/gfxwj/201002/79d42b9c8b3f47ee91000d31de116784.shtml)。

## 二、国际术语体系：区分因素名称和关系强度

### MeSH：区分风险因素与诱发因素

MeSH 是美国国家医学图书馆维护的医学受控词表，主要用于文献索引、编目和检索。以下两项有独立名称、定义和编号，不是任意替换的同义词。

| 概念 | 官方定义的中文概述 | 表达时的区别 |
| --- | --- | --- |
| 风险因素／危险因素，Risk Factors，`D012307` | 根据流行病学证据，与某种健康状况相关的个人行为、生活方式、环境暴露或先天、遗传特征。 | 说明风险背景或统计关联；仅凭风险因素存在，不能认定它造成了这个人的疾病。 |
| 诱发因素，Precipitating Factors，`D015985` | 与疾病、事件或行为反应的发生相关的因素。 | 更关注发病或发作这一事件，不能把所有长期风险背景都自动改称为本次发作的诱因。 |

来源：[MeSH 官方用途说明](https://www.nlm.nih.gov/mesh/meshhome.html)、[风险因素词条](https://meshb.nlm.nih.gov/record/ui?ui=D012307)、[诱发因素词条](https://meshb.nlm.nih.gov/record/ui?ui=D015985)。表中“表达时的区别”为根据定义作出的解释，不是额外制定的医学分类标准。

### SNOMED CT：明确区分关联、先后和直接因果

SNOMED CT 是临床术语体系，其临床发现属性中明确区分以下关系。

| 关系 | 表达的含义 | 不能据此作出的推断 |
| --- | --- | --- |
| Associated with，相关联 | 两项临床概念存在有临床意义的联系。 | 关系本身不确认也不排除因果，不能直接改写为“由它导致”。 |
| After，发生于……之后 | 描述事件或临床发现的先后顺序。 | 时间上在后，并不单独证明前一事件造成后一事件。 |
| Due to，由……导致 | 一个临床发现、事件或操作是另一临床发现的直接原因。 | 不能将仅增加易感性或风险的关系写成直接致病。 |

**官方实际概念示例：**`43959009`，Cataract of eye due to diabetes mellitus，可理解为“糖尿病所致白内障”。这个名称明确表达了因果；它不等于“同时有糖尿病和白内障”。该概念的存在也不代表所有糖尿病患者的白内障都应归因于糖尿病。来源：[SNOMED CT 临床发现属性及 Due to 示例](https://docs.snomed.org/snomed-ct-specifications/snomed-ct-editorial-guide/readme/authoring/domain-specific-modeling/clinical-finding-and-disorder/clinical-finding-defining-attributes)。

## 三、行业工具如何处理患者信息和判断依据

### Infermedica：规范概念 → 收集信息 → 提出候选和问题 → 解释依据

1. **规范输入名称。**症状、风险因素和疾病分别建模，每个概念具有唯一 ID、专业名称及通俗名称，便于程序处理和用户理解。其 ID 属于厂商知识库，不能直接当作 MeSH 或 SNOMED CT 编码。
2. **区分个人信息状态。**每项观察可标记为存在、不存在或未知。“未确认”不会在数据表达上与“明确没有”混为一项。
3. **依据已有资料继续提问。**将年龄、性别和累计观察信息提交给诊断接口，获得候选疾病及下一步问题；用户回答后，加入已有资料再次评估。这是逐步补充信息的过程。

以上处理方式来自其官方 [医学概念说明](https://developer.infermedica.com/documentation/engine-api/build-your-solution/medical-concepts/) 和 [诊断接口及问询流程](https://developer.infermedica.com/documentation/engine-api/build-your-solution/diagnosis/)。

4. **展示判断依据。**解释接口针对一个候选疾病，列出支持观察、冲突观察及待确认信息。这里的“证据”指患者的临床观察，不等于逐项返回的医学论文；“支持某项候选”也不等于确认该疾病或个人病因。来源：[Explain 解释接口](https://developer.infermedica.com/documentation/engine-api/build-your-solution/explain/)。

### 麻省总医院 DXplain：知识库推理 → 候选排序 → 理由与补充资料

| 环节 | 官方公开的处理方式 |
| --- | --- |
| 读取哪些信息 | 症状、体征和检验数据。 |
| 知识库如何表达关系 | 对疾病与临床发现的组合，分别记录该发现出现的频度，以及它对考虑该疾病的提示程度。 |
| 如何得到结果 | 使用改进的贝叶斯逻辑，给出可能解释这些表现的候选诊断及排序。 |
| 如何说明结果 | 给出考虑某项疾病的理由、不典型的表现，以及继续收集哪些临床信息有帮助。 |
| 能否查看医学资料 | 疾病资料包括病因等内容，并附参考文献；其用途是决策支持，不是确定性诊断。 |

这说明 DXplain 并非只输出一个疾病名称，而是同时说明现有资料怎样支持候选，以及还需要补充什么。来源：[麻省总医院 DXplain 官方介绍](https://www.mgh-lcs.org/projects/dxplain)。

## 四、完整官方示例：胸痛信息如何被分别展示

Infermedica 的 Explain 文档提供了一个 **40 岁男性胸痛** 的 API 演示。针对其中一个候选疾病，实际返回内容概述如下。

| 返回类别 | 示例中的具体内容 | 阅读含义 |
| --- | --- | --- |
| 支持证据 | 剧烈胸痛、持续 30 分钟至 8 小时、活动时胸痛等。 | 这些已提供的观察支持考虑该候选疾病。 |
| 冲突证据 | 空列表。 | 本例没有列出冲突观察，不表示已经排除了其他疾病。 |
| 待确认信息 | 是否刺痛、是否在压力下加重、是否在按压时加重等。 | 这些特征尚未确认，不能直接写成患者已有的症状或诱因。 |

**关键区别：**“压力下是否加重”在这份结果中仍是待确认项，因此不能将其直接写成“压力是这位患者胸痛的确定病因”。工具展示了候选判断、支持信息和未知信息三者之间的区别。

这是官方文档的实际示例，不是经本次核实的真实患者病例。目标疾病仅标记为 `c_746`，页面未给出名称，本报告不推测其名称。来源：[Infermedica 胸痛示例原始请求与响应](https://developer.infermedica.com/documentation/engine-api/build-your-solution/explain/)。

## 五、这些资料分别能证明什么

| 资料类型 | 已有内容 | 不应扩大的结论 |
| --- | --- | --- |
| 国内病历规范 | 明确要求记录可能的发病原因或诱因、症状缓解或加剧因素。 | 不等于提供统一的因素编码库或病因推理算法。 |
| MeSH、SNOMED CT | 有受控概念和关系定义，能够区分风险、发作相关因素、关联及直接因果。 | 术语规范本身不负责确认某位患者的真实病因。 |
| Infermedica、DXplain | 有结构化观察、候选判断、补充信息及解释能力。 | 公开示例主要面向候选疾病判断，不能直接声称它们已经实现所有生活方式诱因的因果确认。 |

本文仅核查公开规范和官方文档，未调用商业接口或验证临床准确率。未将本文的归纳解释标记为新的医学标准，也未加入本项目的设计方案。
