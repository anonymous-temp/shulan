# 文件解读恢复验证（v6 / v7，2026-09-16）

## 行为与边界

共享解释器继续处理全文，确定表格值由源单元格复制，模型负责复杂关联与叙述内容。原始评价和标准方向分开，内部来源证据不进入公开报告。

处理质量使用 `complete / partial / unavailable`；质量与临床 `normal / abnormal / pending` 分开。局部恢复耗尽时保留可信结果，无法确认的项目及摘要不进入画像或问答。没有可靠结果的直接解释请求仍返回上游错误；建档可根据用户其余资料继续，并说明附件缺失。

新请求按需恢复缺失区域，当前问答的资料快照不变。同一请求只处理一轮，并发请求共用一轮。历史完整报告不重算，没有持续后台扫描任务。

`test_analysis_json.py` 覆盖完整 JSON、有限拆分、单片失败不取消其余工作、整份时限、成功片复用、必要归档失败不发布，以及最多四个工作协程。`test_trace_integration.py` 使用生产 BSON 留痕适配器验证新 `publication`、修复输入输出和检查点的名称、校验和与主体范围。

来源修订与建档测试覆盖部分结果发布、显式恢复、同一轮并发、旧任务幂等恢复、完整历史缓存、扩展缓存版本、附件全部不可用、缺失提示及问答快照固定。数据库、权限和提交结果未知不会被伪装成附件内容缺失。

同一物理来源补齐单位、日期和评价时，更新来源投影及同一画像事实的缺失字段；冲突值、迟到任务、用户修改、撤回和删除不会被自动覆盖。一次文件批处理中的同内容附件只解释一轮，Report 组合读取复用已结算资料。

合成依赖下的本机 HTTP 冒烟已验证 `qa/create → 202 → qa/status → 200` 并生成首题。该流程使用真实 HTTP Handler 与共享协调器，OCR、模型和持久化依赖均为替身；记录的约 0.4 秒仅用于确认流程可执行，不是线上性能成绩。

统计区分整份处理墙钟耗时，以及各并发调用累计的排队、模型和恢复耗时；累计调用耗时可能超过整份墙钟时间。token 数仅累计供应商实际返回的用量；中断、调用失败或未返回完整用量时 `usageMetricsKnown=false`，不能把该累计值当作完整计费用量。

`tests/fixtures/analysis/recovery_anchors.json` 的 27 项姓名无关指标已逐项核对原 PDF：原九项评价冲突之外，渲染核对第 8 页完整六行评估结果、第 45 页四个零值、第 12 页三个疾病风险评分，以及第 43 页五个脂肪酸评分。包含“失衡／需求高”不转成偏高或偏低、评估值与测量值分类的预期。它是独立诊断锚点，**不是全文金标准**。它同时列出已发现的阈值与方法说明误提取结果，用于拒绝回归。原病例、完整 OCR 和模型回复只保存在本地诊断目录，不纳入仓库。

## v7：日期丢失和首题引文失败的追加修复

随后用户自行进行的 API 建档中，v6 报告保存了 452 项结果，但全部缺少可用日期；画像摄取以 `report_time_unavailable` 跳过。建档另在首题 presentation 阶段发生 `message_evidence_not_found`，查询时三次创建恢复已耗尽。HTTP 202 表示已受理，status 的 HTTP 200 表示状态读取成功，均不表示首题已生成。此次只读核对 MongoDB/Redis，没有修改生产数据。

日期缺陷已独立复现：原校验仅使用项目自身片段中的日期，无法把同一样本的报告日期关联到跨页结果，也未区分送检日和报告日；旧日期匹配还会把数值区间误当日期。PDF 首页和第 22 页明确区分送检日期 `2026-09-01` 与报告日期 `2026-09-03`。v7 按有标签的日期角色、同一报告身份和子报告边界关联日期，原始证据保留在内部。跨报告、日期冲突、无日期子报告、非法日期和参考文献均有回归。来源绑定继续使用原物理身份，版本升级不重复建立同一事实。

首题的原始错误模型回复未归档，因此不能断言具体失败引文。已修复可复现的输入契约问题：报告改为完整可引用事实行，保留结果类别、标本、方法、所属检查和日期；超过预算时省略完整条目。引文只规范空白，数字边界和来源仍严格，不能把 `10` 截成 `1` 或丢失比较符。内部失败诊断保存引文位置、来源及匹配边界，不保存健康原文，也不新增公开响应字段。
