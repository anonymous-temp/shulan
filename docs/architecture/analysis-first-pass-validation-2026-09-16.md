# 文件解读首轮稳定性验证（2026-09-16）

> 历史记录：下文验证的是本次故障诊断前的 v5 修复方案，不能作为 v6 的上线验收依据。真实 119 页样本随后暴露了重复背景、标准评价冲突和无来源误提取问题。v6 已替换相应设计，当前结果见 [文件解读恢复验证](analysis-recovery-validation-2026-09-16.md)。匿名旧模型回复仍保留，用于验证协议升级后不会盲目信任旧输出。

本次实现用于体检报告解读、建档问答共享的上传文件流程。模型仍负责全部指标提取，公开响应保持兼容。没有重算历史报告，没有写入生产数据库。

## 实现与离线验证

- 根据 DocMind 单元格与跨度准备来源记录；双语名称和换行名称对应一个结果单元格，关联不确定时保留原始单元格结构。
- 首次调用前按最多 80 条候选记录、8000 字符分片；结构化输入把表头和背景计入字符预算。完整记录不拆散，超长单条独立处理。纯表格在不增加调用数、不超过上限的条件下均衡分片，例如 120 条分成 60＋60，减少并发批次中最慢一片的等待。
- 模型只生成 observations，后端生成 lab/microbiome 的兼容 expansion；归一化前校验来源、覆盖、类型、结果与元数据。相同来源只有一致时才合并；不同日期、方法和标本保留。
- 输出恢复最多一轮；截断片只拆一次，来源错误只修复相关记录。耗尽后保留检查点，停止 QA 外层自动重跑。传输故障沿用既有有界恢复。
- 只复用当前版本、同一来源身份并通过同版本校验的未完成结果；原始文件及 DocMind 归档可继续复用。
- 545 项相关离线回归通过，包括两个公开接口、共享处理、QA 恢复、模型适配、检查点及画像摄取。Ruff 和 `git diff --check` 通过。

`tests/fixtures/analysis/docmind_bilingual_spans.json` 保留真实失败表格的脱敏单元格结构；`first_pass_model_replay.json` 保存本次新版 9 次处理的匿名模型输入和回复。回放按输入全文精确匹配，验证最终代码生成的模型输入与实测一致，并重新通过全部来源校验、归一化和质量检查。

## 受控模型实测

模型为 `DeepSeek / deepseek-flash`。两版均使用 16384 tokens 输出上限、4 路并发、temperature=0、JSON 模式、无思考模式。各次任务使用新的内存状态，不复用结果检查点。两版使用相同供应商缓存策略，远端命中量不完全相同，保留在逐次 usage 中。

基线是本轮输入准备、来源校验和有界恢复改造前的代码，已经包含此前的 observations 单份输出与 16384 tokens 配置。因此本对照不是与最初 8192 tokens、重复生成 expansion 的故障版本比较。

实测只发送脱敏或合成文本，回放 DocMind 归档，不访问 MongoDB、Redis 或 DocMind。为准确限制请求次数，两版在基准脚本内均关闭 SDK 传输自动重试，生产重试策略未因此改变。

首批试跑用了 14 次调用，在影像检查器把结尾句号误判为内容变化时停止。核对原始回复后，仅放宽句末标点差异，仍严格检查检测值、日期、标本和影像内容，并加入回归测试。随后完成整组新旧对照，共 21 次调用；累计 35 次，未超过批准的 36 次及 15 分钟窗口。两次脚本实际运行合计约 188 秒。

## 验证边界与复现

实际上传、远端 DocMind 解析、数据库落盘、生产排队及 QA 首题生成未计入本次实测；端到端生产任务耗时尚未验收。基准直接调用共享解释器，QA 外层不自动重跑的行为由离线测试覆盖，不能将其表述为已完成真实 QA 创建全流程压测。对缺少可靠表格结构的自由文本，目前可校验字段结构和结果有效性，无法机械证明语义上的全部项目均已识别。

实测完成后增加了背景字符预算和父子报告不同标本/方法的合并保护。这些边界变更经全部离线回归及 9 次实测回复的精确输入回放验证，不另行调用模型。

复现入口为 `python -m tests.api.scripts.analysis_first_pass_benchmark --help`。需要提供修改前 service.py、提示词快照、当前三项 SHULAN_LLM 配置和输出位置；`--live` 显式开启付费请求，`--max-model-calls`、`--total-timeout` 限制单次脚本预算，`--fail-fast` 在新版首轮正确性失败时停止。跨多次运行的累计预算需要调用方统一限制。

本次原始输出在本机临时目录 `C:/Users/MSR/AppData/Local/Temp/shulan-analysis-first-pass-run1.json` 和 `shulan-analysis-first-pass-run2.json`，包含输入、回复、来源记录、使用量、排队及模型时长。临时归档不作为持久化交付依赖，匿名新版回复及本报告已纳入工作区。

## 14:10 线上留痕异常的回归修正

线上出现 `adapters/analysis/document_trace.py:85 ValueError: 未知文档留痕内容类型`。本轮新增的 `analysis_metrics` 和 `analysis_input/output_00000_repair` 没有同步加入 MongoDocumentTraceStore 的名称白名单：正常完成会在统计归档时失败，局部修复会在输入归档时提前失败；finally 中的统计写入还会覆盖先前异常，形成 `ValueError -> ValueError`。

此前流程测试和模型实测使用允许任意名称的内存留痕，已有 Mongo 适配器测试只独立验证 DocMind 等既有归档，没有覆盖新流程与生产适配器的组合。这是实现和测试遗漏，前述模型回放结果不能作为真实存储链路成功的依据。

已补齐明确的类型白名单，保留未知名称和非法路径拒绝规则，并在类型错误中记录具体名称。统计归档故障独立记录日志，不再推翻成功结果或覆盖原始业务异常；原文、模型回复、解释结果等必要归档仍遵循保存失败则不发布的要求。

新增 `test_trace_integration.py`，通过生产 MongoDocumentTraceStore 执行 BSON 编解码、分块、校验和及主体范围校验，仅底层集合使用内存替身。修复前复现 11 个失败；修复后新增 21 项回归通过，相关整体回归 **566 项通过**，Ruff 与 `git diff --check` 通过。覆盖两个入口的首次完成、局部修复、恢复耗尽、截断拆分、统计故障不覆盖业务结果、必要归档故障阻止发布，以及修复后复用 DocMind 与已保存局部恢复计划。没有调用真实模型、生产 MongoDB 或部署服务器。
