# 建档问卷因素术语规范与工具调研

> 状态：医学术语与行业工具调研，以及项目设计建议；生产初版采用其中的关系和证据分层原则，具体实现范围见[分析流程](record-questionnaire-evidence-workflow.md#5-生产初版的数据流)，本文不是 API 契约。
>
> 调研日期：2026-11-06。2026-11-07 补充 `feature/record-questionnaire` 工作区的 AION `v0.6.0` 接入边界；原医学调研与工具比较不变。

## 1. 结论与适用范围

医学已有危险因素、诱发因素、病因、加重或缓解因素等表达，术语体系也能支持概念编码和关系建模。规范问卷分析时，需要分别控制“因素名称”“与具体健康问题的关系”和“个人证据支持程度”，不能仅要求模型使用专业词语。

本次查到的资料没有提供一套可以直接覆盖全部建档场景的统一“疾病—诱因—问卷判定规则”目录。可以组合临床术语规范、医学知识库和项目判定规则；不能把任一术语库描述为能够直接确定个人病因的现成引擎。

| 内容层级 | 本文如何使用 | 权威范围 |
| --- | --- | --- |
| 现有临床规范与术语体系 | 第 2 节介绍病历规范、MeSH 和 SNOMED CT | 支持术语含义、临床记录分类或概念关系；不直接给出本项目算法 |
| 行业工具公开实现 | 第 3 节介绍 Infermedica、Ada 和 DXplain | 支持厂商文档或论文明确披露的机制；不代表完整内部实现或医学效果验证 |
| 项目设计建议 | 第 4～6 节提出术语目录、证据状态、输出校验和验收 | 关系与来源分层用于初版，术语目录仍为治理建议；不是国家标准或已上线证明 |

本文沿用业务讨论中的“诱因分析”名称。建议在内部建模时以“候选相关因素”作为集合名称，再准确标注每条关系；该总称是项目建议，不是医学标准规定的统一名称。

## 2. 现有医学表达与术语体系

### 2.1 临床记录中的区别

卫生部 2010 年《病历书写基本规范》第十八条在现病史中分别记录发病的“可能的原因或诱因”和症状的“缓解或加剧因素”，既往史、个人史及家族史另有记录位置。这说明健康背景、发病原因和症状变化条件具有不同含义，不能全部写成诱因。[S01 卫健委原文](https://www.nhc.gov.cn/wjw/gfxwj/201002/79d42b9c8b3f47ee91000d31de116784.shtml)

下表是依据所引资料整理的术语使用说明，不是一套官方统一、互斥的分类表：

| 术语 | 常见英文对应 | 所表达的关系 | 使用时必须保留的区别 |
| --- | --- | --- | --- |
| 危险因素／风险因素 | Risk factor | 与某疾病或不良结局风险增加有关 | 总体风险关联不等于该患者的确定病因 |
| 诱发因素／诱因 | Precipitating factor；具体场景也使用 trigger | 与疾病发生、某次症状出现或发作有关的触发关系 | 需明确所讨论的疾病或事件及时间关系 |
| 加重因素 | Aggravating / exacerbating factor | 与已有症状或病情加重有关 | 加重已有症状不等于导致疾病首次发生 |
| 缓解因素 | Relieving / alleviating factor | 与症状减轻有关 | 症状缓解不自动等于病因消除或治疗有效 |
| 病因／致病因素 | Etiology / etiologic factor | 疾病发生的原因或致病来源 | 因果表述需要匹配的医学依据和个体判断 |
| 相关因素／待核实因素 | 依具体语境表达 | 有关联或核实价值，关系尚需进一步明确 | 这是候选阶段的表达，不应伪装成确定结论 |

“危险因素→诱因→病因”不是固定的证据升级顺序。同一因素可能同时具有多种作用，需绑定具体结局与阶段；这些关系也不能作为因素本身永久、互斥的分类。MeSH 将 Risk Factors 与 Precipitating Factors 分别建项，其 Causality 概念涵盖多种因素对结果的作用。[S02 Risk Factors](https://meshb.nlm.nih.gov/record/ui?ui=D012307)、[S03 Precipitating Factors](https://meshb.nlm.nih.gov/record/ui?ui=D015985)、[S04 Causality](https://meshb.nlm.nih.gov/record/ui?ui=D015984)

### 2.2 MeSH 适合统一检索概念

美国国家医学图书馆的 MeSH 是用于文献标引、编目与检索的受控词表。Risk Factors 的标识为 `D012307`，定义强调行为、生活方式、环境暴露及先天或遗传特征与健康状况的流行病学关联；Precipitating Factors 的标识为 `D015985`，描述与疾病或事件发生有关的因素。[S02](https://meshb.nlm.nih.gov/record/ui?ui=D012307)、[S03](https://meshb.nlm.nih.gov/record/ui?ui=D015985)、[S05 MeSH 用途](https://www.nlm.nih.gov/mesh/meshhome.html)

在本项目中，可借鉴其概念与同义表达组织检索词，但这两个通用标识不能替代具体因素目录，也不能单独支撑某项“疾病—因素”关联。中文译名、专科含义和适用情境仍需医学审核。

### 2.3 SNOMED CT 适合借鉴概念和关系建模

SNOMED CT 为概念提供唯一标识、完整指定名称（FSN）和同义词，并通过语言参考集确定首选名称（PT）。名称用于表达概念，不能因为字面相似就认定两个概念等价。[S06 SNOMED CT 术语结构](https://docs.snomed.org/snomed-ct-practical-guides/snomed-ct-translation-guide/3-snomed-ct-as-a-health-terminology)

其临床发现概念模型区分：

- `Due to`：直接因果关系。
- `Associated with`：临床相关关系，本身不肯定或排除因果。
- `After`：事件发生的时间先后，本身不肯定或排除因果。

上述定义来自概念编制规则；官方同时提醒避免过度使用含义宽泛的关联属性。因此，它适合支持“概念与关系分开”的设计，不应被当成个人因果推断算法，或把所有关联都映射为同一个属性。[S07 Clinical Finding Defining Attributes](https://docs.snomed.org/snomed-ct-specifications/snomed-ct-editorial-guide/readme/authoring/domain-specific-modeling/clinical-finding-and-disorder/clinical-finding-defining-attributes)

如后续实际引入 SNOMED CT，应核对版本、授权和中文映射，不能编造标准编码，也不能将自行翻译的名称标为官方中文首选名。[S08 获取与授权说明](https://www.snomed.org/get-snomed)

## 3. 企业与机构工具的公开做法

### 3.1 Infermedica

Infermedica 将症状、风险因素和疾病建为不同医学概念，使用唯一 `id`、专业名称 `name` 和通俗名称 `common_name`。症状关系还包括加重因素和缓解因素，避免将所有信息混为风险或病因。[S09 Medical concepts](https://developer.infermedica.com/documentation/engine-api/build-your-solution/medical-concepts/)

其个人证据采用 `present / absent / unknown`，官方明确否认与未知不能互换；分析接口根据证据返回候选结果及后续问题。解释接口另行列出支持、冲突和未知证据。这种接口表达支持可检查的候选判断，并不意味着通过问卷已经证明个体因果关系。[S10 Diagnosis](https://developer.infermedica.com/documentation/engine-api/build-your-solution/diagnosis/)、[S11 Explain](https://developer.infermedica.com/documentation/engine-api/build-your-solution/explain/)

其医学内容由编辑从资料中录入关系及概率特征，保留参考来源，并经过审核和回归检查。可借鉴的是概念、个人状态与证据治理；公开文档没有提供可以直接复制的完整医学模型。[S12 Medical content](https://developer.infermedica.com/documentation/overview/medical-content/)

### 3.2 Ada

一篇 2020 年由 Ada 员工参与的一手研究描述：医生整理并审核文献，形成疾病、症状和临床发现知识模型；知识库定义贝叶斯网络，系统进行近似推理，再通过信息论方法选择后续问题。症状时间、强度及流行病学先验参与建模。[S13 JMIR 原始研究](https://humanfactors.jmir.org/2020/3/e19713)

这说明“根据当前候选和信息缺口选择问题”有现成研究实践。该论文描述的是当时的工具，不能据此断言 Ada 当前版本的完整实现，也不能将其概率计算直接移植为本项目诱因评分。

### 3.3 MGH DXplain

麻省总医院的 DXplain 接收症状、体征和检验资料，通过知识库及改进的贝叶斯逻辑产生候选诊断排序。其疾病与临床发现之间保存出现频率、提示程度等属性，并输出考虑理由、不典型表现和建议继续收集的信息。[S14 MGH 官方项目说明](https://www.mgh-lcs.org/projects/dxplain)

可借鉴的做法是同时呈现支持信息、不符合之处及下一步核实项。其公开定位是诊断决策支持，不是可自动确定个人病因的系统；本文不据此推断其未公开的评分公式。

### 3.4 对本项目的借鉴边界

上述工具的主要对象包括候选疾病和临床发现，而本项目还要核实与风险有关的行为、暴露及其他因素。二者不能直接等同。可以借鉴概念编码、证据状态、信息缺口和可解释结果，再依据本项目医学知识建立因素关系；不要求采购上述服务、复制其知识库，或改造成相同的诊断产品。

## 4. 项目设计建议

本节区分长期建议与首期实现。初版采用受控关系、原始证据引用和条件匹配，不引入人工审核工作流；统一医学编码目录属于后续治理建议，不声称已接入 SNOMED CT 或 MeSH 编码。

### 4.1 建立受控术语目录

因素目录至少保存内部编号、规范中文名、定义、同义表达、可选标准映射、版本及审核状态。医学人员确认首批词条和语义边界，后续新增或合并词条需要保留变更记录。

长期目录治理可以由医学人员维护概念与同义词。初版不设置逐条人工审批；因素名称须有实际医学材料支持，并限制关系类型。不能编造标准编码、强行匹配近义概念或改写用户原话；不因未接入编码目录而输出虚构的标准概念。

同义词归一化不能抹去程度和条件。例如“偶尔晚睡”不能仅因含有“晚睡”就被映射为睡眠不足；“每周运动一次”应保留频次，是否满足某项医学定义另按明确依据判断。

### 4.2 分开保存关系与个人证据

| 内部对象 | 建议记录 | 要解决的问题 |
| --- | --- | --- |
| 因素概念 | 编号、名称、定义、别名、标准映射和词表版本 | 同一概念不因模型措辞不同而重复或漂移 |
| 医学关系 | 因素、目标风险或症状、关系类型、适用人群、时间及程度条件 | 不把相关、诱发、加重和病因混写 |
| 知识依据 | 来源 ID、原文定位、来源版本、研究或指南信息、适用条件 | 关系有可追溯依据，AI 摘要不冒充原文 |
| 个人资料 | 主体、原话或报告内容、时间、单位、否认范围、来源定位 | 不把家族情况、历史陈述或条件性否认改写为本人当前事实 |
| 条件状态 | 存在、否认、未知或冲突，以及逐项依据 | “未提供”不等于“没有”；默认未知不伪装为主动陈述 |
| 候选判断 | 支持、反证、待核实条件、关系结论及分析版本 | 记录判断怎样随答案变化，避免只保存一段解释文案 |
| 问题关联 | 题目与选项版本、信息目标、候选因素、待验证条件 | 回答能够更新对应条件，而非只进入通用画像提取 |

“知识依据的质量”“个体条件的匹配程度”“因素存在性”是不同维度。不得把检索排名、模型自报信心或几个肯定选项转换为医学证据等级、因果概率或确定病因。若采用正式分级方法，需另行明确适用体系和审核流程；当前项目相关来源仍可保留未分级状态。

### 4.3 按证据约束结论表达

| 已有依据 | 可表达的内容 | 不应自动产生的内容 |
| --- | --- | --- |
| 用户明确报告某行为 | 该行为存在，并保留时间、频次等限定 | 该行为就是当前疾病的病因 |
| 只有指南中的一般风险关联 | 该因素与指定风险有关，是待核实候选 | 该用户具有该因素或已因此患病 |
| 用户描述某事之后出现症状 | 记录时间关系及自述来源 | 仅凭先后顺序认定因果 |
| 医学关系适用，个人条件得到支持 | 说明支持的是风险关联、可能诱发或加重等具体关系 | 无依据地升级为“已经找到病因” |
| 原始医疗记录含明确病因判断 | 按原记录、判断者、日期和确定程度引用 | 改写成系统独立确诊，或移用于不同主体和时间 |
| 回答为空、未知或有冲突 | 保留未核实或冲突条件，生成必要补充项 | 当作否认、自动排除全部风险或补造结论 |

这些规则约束语义，不建立必须逐句照搬的话术库。用户侧仍直接呈现有依据的解释和具体问题，不反复输出“信息不足、无法判断”等拒答式内容；内部状态保留真实的不确定性。

### 4.4 在现有架构中分工

建议沿用现有应用层与 Graph：知识网关提供依据，模型完成候选组织、条件匹配和自然表达，程序检查词条、引用、主体、版本和状态。模型输出优先携带概念编号、关系类型及证据引用，展示名称由已审核目录解析，避免仅用自由文本保存结论。

程序能够检查引用是否存在、关系是否在允许范围、个人证据状态是否与声明冲突；不能仅靠 ID 存在就证明医学关联成立。关系适用性仍需医学审核的规则、来源内容判断和真实模型验收。

局部无效条目进入既有修复或待核实路径，保留有效内容与用户资料。不要用全局关键词替换删除“导致”等词：原报告和用户陈述可能合法包含这些词，应分别处理来源引用和系统新增断言。

## 5. 与五步分析及答案更新的衔接

| 原有步骤 | 本文建议增加的表达约束 |
| --- | --- |
| 第一步：读取资料并识别异常 | 区分检查事实、症状、背景和行为，保留主体与来源，不提前统称诱因 |
| 第二步：综合分析健康风险 | 风险条目有明确目标和个人依据，不把异常值直接当成确诊 |
| 第三步：循证形成候选诱因 | 候选映射规范概念，分别保存目标、关系类型、医学依据和适用条件 |
| 第四步：匹配已有个人信息 | 分开判断因素是否存在、条件是否匹配；保留反证、未知与冲突 |
| 第五步：针对缺口生成问题 | 问题验证具体条件，问卷与健管师清单去重，不诱导客户支持候选 |
| 答案提交后的更新 | 用冻结题目、选项和原答案更新同一候选的条件及支持状态，生成新的分析版本 |

这组约束细化[五步流程及答后更新](record-questionnaire-evidence-workflow.md)，不增加自动无限追问或修改首次答案的权限。健管师沟通结果仍须通过明确的外部接入方式取得，不能把待问清单当作已发生的患者陈述。

以下为抽象设计示例，不代表医学判定规则：

1. 知识资料 K 支持因素 F 与风险 R 的某种关联，适用条件为 C1、C2。
2. 现有资料已支持 C1，C2 未知，因此生成问题 Q 核实 C2。
3. 用户肯定回答后，只更新 C2 对应的个人事实，再重新评估关系是否适用；否认保留其范围，空答保留未知，冲突不强行覆盖。
4. 即使 C1、C2 均满足，结论仍受 K 的关系类型和证据范围约束，不能从一般风险关联自动变成个人病因。
5. 原始问卷和答案不变，新的匹配结果单独保存；画像仍只摄取有来源的用户事实，分析结论作为派生材料供后续功能使用。

初版按[生产数据流](record-questionnaire-evidence-workflow.md#5-生产初版的数据流)连接知识网关、候选条件、冻结题目映射和答后重评。统一编码目录与正式医学术语映射未纳入首期。联网回退依赖 AION `v0.6.0`，只有自有知识库无适用材料才调用；独立检索词与模型正文分离，SDK 来源摘录及追踪单独保存。当前返回的有界摘录不是全文，检索成功不等于医学证据等级、材料适用或个人因果关系成立；完整病例仍需检查来源与结论的实质关联。问卷和答案 Schema、会话门禁及画像事实边界保持不变。

## 6. 实施前产物与验收建议

优先形成经医学审核的因素目录、关系适用条件表、个人证据状态规则和表达案例集，再接入现有知识网关及五步流程。首批范围依据实际覆盖的健康问题确定，不由模型自行扩展为全病种词库。词条及关系更新保留版本，既有问卷和分析结果继续引用生成时的快照。

| 验收场景 | 预期结果 |
| --- | --- |
| 同义表达、模糊措辞及目录外概念 | 保留原话和程度，不强行归类或编造编码 |
| 同一因素关联不同结局 | 各自使用对应的关系和依据，不套用永久“诱因”标签 |
| 知识引用存在但不支持结论 | 不得仅凭引用 ID 有效就发布该关系 |
| 一般关联、时间先后和个体因果混淆 | 结论维持证据允许的关系，不能自行升级 |
| 肯定、否认、未知、空答及冲突 | 分别更新条件，空答不确诊也不排除 |
| 亲属、时间、数量和条件范围变化 | 按真实主体与范围判断，避免过度归一化 |
| 问卷与健管师清单获取同一信息 | 按信息目标去重；未取得沟通结果时保持未知 |
| 原报告已有明确医学判断 | 忠实引用判断者及确定程度，不用通用措辞过滤误删 |
| 重复提交、恢复及术语版本更新 | 原始快照与回执不变，派生结果版本可追溯 |
| 用户侧表达 | 术语准确且自然，不循环复述主诉、不使用固定陪伴模板或内部失败提示 |

真实模型验收应检查医学关系、候选完整性、反证处理和问题区分能力；程序校验通过不能替代这些评估。本次文档整理不改变既有开发测试要求，也不意味着上述能力已经验收。
