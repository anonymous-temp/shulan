# 健康分析问卷生成与审核需求

> 方案讨论稿，更新于 2026-11-18。

本专题适用于 `POST /api/v1/health-analysis` 返回的补充问卷 `advancedSurveySchema`。目标是让问卷补齐本次资料真正缺少的信息，题干自然、可直接回答，选项贴合题意和用户情况，同时控制同步请求的审核耗时。接口的四项输出和历史答案格式沿用现有约定。 [健康分析接口](../api/API.md#生成健康分析) · [流程及实现方案](../architecture/health-analysis-questionnaire-review-plan.md)

## 1 生成和审核共用的规则

同一份规则清单同时约束初稿生成和发布审核。每条规则说明适用范围、什么情况下通过、发现问题后允许怎样处理。整卷和单题及选项是同一次联合审核的两个维度。

### 1.1 三个基础主题逐项补问

首卷先逐项判断主诉或健康目标、个人疾病史、血亲家族史。依据本次可用的体检解读、可归属本人的群聊和历史问卷实际答案，缺哪个主题就询问哪个主题。若主诉和个人疾病史已有答案、只有家族史缺失，则只补家族史。多项缺失时按上述顺序安排在生活题之前。

历史问卷的题目与实际答案分别使用。发过基础题且答案为空时，该主题仍需补问。已有明确的肯定、否认或未知回答按照现行覆盖语义处理。历史生活题即使未答，仍按现行规则参与去重。 [健康分析现有需求](health-analysis-requirements.md)

### 1.2 整卷的题目组成

生活题从已有生活习惯目录选择，可采用题库模板或按资料拟写。整卷用本次应问的基础主题和合格生活题组装。审核时核对基础主题是否问对、问卷说明与实际作答方式是否一致、卷内是否重复采集，以及生活题是否在本次允许采集的范围内。

题量延续现有规则，目标为 10～20 道，最多 20 道，缺失的基础主题计入总数。删除不合格题后需复核题量和信息覆盖情况。当前范围内可以发布的题确实不足时可以少发。确认基础主题已覆盖且没有合格新题可问时，问卷返回 `null`。

### 1.3 单题的适用性与题干

| 检查内容 | 判断要求 | 处理方式 |
|---|---|---|
| 题目对该用户是否适用 | 判断依据来自本次可用资料、题目的明确前提和现有适用性规则。例如已明确从不饮酒，单次饮酒量不适用。 | 有依据确认不适用的生活题可以删除，并保留原因。 |
| 题干是否清楚、自然 | 一个题干对应一个明确采集目标，用户读完能知道应回答什么。审核定位抽象、机械、逻辑不清或预设用户存在某种情况的措辞。 | 有采集价值的题保留信息目标，调整题干或必要说明。 |
| 题干是否表达原选题目标 | 题目实际问到的信息与选题目标一致。例如运动频次问运动几天或几次。 | 在原目标内修正问法。需要改变采集目标时，重新走选题。 |

本次必问的基础主题若题面不合格，应换成能正确采集该主题的问法。得到该主题已有答案的有效依据后，可重新计算本次应问清单。

### 1.4 选项的适用性与表达

选项应直接回答题干，并与本次用户情况、题型及采集维度相符。时点题用具体时刻，时长题说明合计范围。单选项应覆盖题干的可回答范围，区间或状态的边界清楚可区分。分类项保持同一层级，具体食物可用于解释其所属类别。多选互斥项沿用现有协议。

题干合格而选项有问题时，优先修正选项。指定题目的规则按采集目标生效。若已经确认某道题采用固定题型和选项清单，按该清单核对。若确认允许在给定范围内生成，则审核必有项、允许范围与选项含义。

新生活题的具体选项已经覆盖可回答范围时，移除「不清楚」「记不清」等占位选项，无法判断可留空。「时间不固定」「没有运动」「从不饮酒」是实际情况，按原义保留。发现具体选项缺档时，优先补齐缺档。已发布的历史问卷继续按各自提交的 Schema 解码，保留已选的未知答案。

| 采集目标 | 生成和审核口径 |
|---|---|
| 准备睡觉的时点 | 询问开始准备睡觉的具体时刻。基础档为晚上22点前、22点到次日0点前、次日0点及以后，可选时间不固定。22 点和 0 点分别归后一个区间。 |
| 每日实际睡眠时长 | 按每日合计实际睡着的时间回答，计入午睡。各档为不足6小时、6至不足7小时、7至不足9小时、9小时及以上。 |
| 休息时间安排 | 放在工作、学习或家务之外的生活场景中，询问平日固定安排、只在休息日固定安排、临时安排或通常不专门安排。 |
| 正餐食物构成 | 多选同一层级的食物类别，基础类别为谷薯类主食、蔬菜类、水果类、畜禽肉类、水产类、蛋类、豆类及豆制品。 |

## 2 审核和发布要求

1. 问卷审核针对实际待返回的整卷。同一次模型调用给出整卷结论和逐题结论，发现问题时定位对应的规则、题目及原因。能在本轮明确修正时，同时给出删题意见或改稿。
2. 首次通过时，问卷的模型审核目标为一次调用。程序执行结构、题量和必问主题等可直接判定的检查，并复用已有资料覆盖、去重和适用性结论。
3. 应用修改后重新检查最终稿。纯删除且原有裁决仍有效时，由程序核对必问主题、题量和覆盖。新增题目、改变题意或修改选项含义时，复审改动题和受影响的整卷规则。
4. 只有当前稿通过发布校验，才将它填入 `advancedSurveySchema` 并返回完整结果。仍有问题且纠正预算用尽时沿用生成失败 `502`，达到同步总时限时沿用超时 `504`。运行记录需要能查到各轮意见、实际修改和最终裁决。

## 3 验收场景

| 场景 | 预期 |
|---|---|
| 已有主诉和个人疾病史，家族史缺答 | 基础题只补问家族史。 |
| 三个主题都已答或都缺答 | 都已答时直接评估生活题。都缺答时按顺序询问三项。资料与历史题均空时覆盖现有 13 题基础卷场景。 |
| 已明确从不饮酒，草稿含单次饮酒量 | 标明资料依据，删除不适用题，再核对整卷覆盖与题量。 |
| 生活题信息目标有效，题干抽象或机械 | 改成用户可以直接回答的问法，并复审该题。 |
| 时点题在 22 点、0 点交界处重叠，时长题使用频率选项或遗漏午睡 | 修正时间口径或选项，复查题意和区间边界。 |
| 休息题措辞抽象，正餐选项混合类别与具体食物 | 使用明确生活场景提问，将选项统一为同一层级。 |
| 完备生活题有未知占位项 | 移除占位项并复审，保留明确状态及可留空行为。 |
| 修订题干与已发送旧题对应同一采集目标 | 旧卷按原选项解码，新卷识别旧题并保留历史引用。 |
| 改写后与本卷其他题重复 | 定向复审指出相关题目，修正后再判断发布。 |
| 正常草稿与确有修改的草稿 | 正常草稿的一次联合审核给出两个维度的结论。发生修改时只为需要重新判断的内容追加模型调用。 |
| 覆盖耗尽、持续不合格、总超时 | 分别验证 `null`、`502`、`504`。 |

## 4 待定的业务细则

- 继续确认其余题目的必有项和允许范围。
- 确认特定问题何时允许补选项、调整题型、合并或拆分。当前方案以题干、说明、选项的局部调整，以及基于明确依据的不适用删题为默认范围。
- 依据真实场景的首轮通过率、修复效果和延迟，确定改写及复审预算。工作区试做中的次数为讨论参考。
