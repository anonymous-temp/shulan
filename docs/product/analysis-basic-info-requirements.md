## 1. 用户决策与范围

同一报告功能最终只保留一套当前提示词、校验、两阶段预算与合并算法。调用方提交文件和明确主体，不选择 v12/v13 或执行器修订；产物如实保留实际执行身份、固定轮次、引用和摘要作为技术元数据。

用户明确没有生产数据，本期不做历史缓存、历史执行器、旧格式解码或旧任务版本回退。此前关于维护旧版本分派与升级后复用旧缓存的要求被替代。当前同一实现内的文件去重、幂等、固定轮次与可恢复部分结果继续有效。

Analysis 负责文件到原文、模型到结构化结果、字段证据及当前检查点；Document 负责固定资料、贡献和交付；Profile 负责事实、可信度比较、当前值和人工治理。本轮 current 端口不写 Profile，不代改 Document、Report 或组合根，不导入未合分支假装已集成。

## 3. 当前字段规则

basicInfo 包含 name、gender、age，未知为 null。姓名 trim 后非空，不另加本域长度截断，受整体容量预算约束；脱敏、遮盖或无法辨认姓名只留原文、候选和未决原因。

性别规范为男/女，原文明示的 Sex/Gender/性别单一 Male/Female 或 M/F 可规范化；不从姓名推断。报告年龄是0～150有限年数值，0合法，bool非法；明确月龄按月数/12，岁加月按对应年数保留足够精度及直接原文。无日历依据时不自定天数换年，不把肠道年龄等评分当实际年龄。

basicInfoMeta 逐字段记录 status、sourceReliability、observedAt、reason、evidence、subjectStatus、subjectRef、subjectEvidence、candidates。status 为 extracted/not_found/unresolved/conflicting；报告档位只允许 low/medium 或 null，不允许模型给 API 确认使用的 very_high。

供 Document 固定归档与 Profile 接收使用的 observedAt 为 YYYY-MM-DD 日历日期、带完整日历日期及 T 或空格分隔的 ISO 时间，或 null。明确的 YYYYMMDD 日期及带 T 或空格的紧凑日期时间先规范化。校验原始时区偏移的各组成部分，并保留来源的时钟精度和小数位。例如，20260901T0915+0800 规范化为 2026-09-01T09:15+08:00。时间不明确、无效或日期与时间分隔符不受支持时只清空 observedAt，保留已验证的字段值、档位、原文与主体证据，避免时间格式错误阻断整份报告归档。

extracted 必须有可确认的单一受检者、单值、理由和直接引文。subjectRef只是原文锚点，不是后台主体ID；缺少锚点可以为null，但不能跨段拼接不同受检者。每个规范化候选也须由自身引文支持，非法候选不能制造真实冲突；原始输出保留在轨迹。

跨片段、格式修正及同一原文的基础核查统一汇集同字段已验证单值与待核实候选；出现互斥值时顶层为null/conflicting，并保留各值的原文、AI档位和主体依据。已提取值因互斥而转为待核实时，也保留其类型化值，不能以后从引文猜回；合法候选不能被已有单值吞掉。候选即使只剩一个也不由程序升级为extracted，同值待核实候选不升级已有单值的档位。已提取同值仍可保留更高的原AI档位；年龄42与42.0等价，bool仍非法，姓名和性别不做模糊合并。AI显式给出的subjectStatus=ambiguous是独立主体屏障，即使该片段没有可用值或候选也保留；非法候选被拒与明确的多主体判断不能混同。

同一已验证证据的派生汇总视图不得被重复算作新的受检者或独立来源；去除视图重复不解除跨片段无锚点的主体隔离，也不覆盖显式 ambiguous。

## 4. 公开准备与纯读

prepare_document 要求 user_id、subject_id 和原有文件参数，不接版本、selection、发布模式或内部执行器；只运行唯一 current 算法，固定不发布，返回实际 preparation_binding、input_snapshot、output_selection 和 structured_data。

read_prepared_round 要求明确 user_id、subject_id、document_id、interpretation_round。公开结果包含上述scope、固定绑定、完整 parsed_document、interpretation 和真实 output_selection。通过归档清单定位指定轮次，不能用最新解释或payloadRefs替代，必须核对身份、两个摘要和重复读一致性。

当前完整文件按内容身份与归属复用；可恢复 I/O 故障继续同一当前执行。首次固定前，按当前观察时间规则处理根和子报告的基础字段，包括从已完成检查点或已保存解释恢复的结果。固定写入已成功时沿用原归档引用和摘要。retryable 部分内容按原协议建立新固定轮次，原轮次保持不变。没有旧数据迁移或强制重解析功能。

## 5. 过渡默认与最终删除

当前端口保留真实当前修订。现用默认 HealthReportInterpreter、原默认注册及 health_report.txt 暂留真实原实现，因为已合 develop 的 Document 正式消费仍要求原执行身份。禁止把 current 结果标成旧身份绕过检查，禁止 current 失败后调用过渡实现。

这是用户批准的串行合入阶段，不是历史兼容或最终双业务模式。Document 当前消费适配等前置提供方用户合入后，Analysis 与组合根在阶段5切换唯一当前入口，删除旧默认算法、原提示词和过渡接线；完成前不得声称全项目已单算法。
