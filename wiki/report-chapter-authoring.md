# 评估报告：多来源证据与按章成稿

> 本文描述的是七章模板时期的按章成稿流程。评估报告已改为六章（`assessment.v2`），现行内容规格、生成流程与时间预算见 [评估报告六章内容规格](report-assessment-v2.md)，样版渲染与组件见 [样版渲染与组件说明](report-assessment-v2-render.md)。本文的证据通道、DeepSeek 工具接口与配置说明仍然适用。

本文说明分支 `feature/report-deepseek-evidence-20261115` 对评估报告（`type=evaluate`，七章模板）生成链路的改动。改动只在本地用一例真实资料跑通，未做多病例评测，也未在测试环境联调回调；不代表已上线。

## 改动前的问题

以同一例资料实跑改动前的流程（约 6 分钟）：

- 参考文献 0 条。召回 1,574 条记录，入选 0 条：临床问题的检索词是报告里的分组名加英文后缀（如“糖代谢风险（空腹C肽偏高…） management guideline”），字面匹配和适用性筛选都无法通过。
- 每格一两句，全篇约 1.6 万字；菌群、营养、通路三章的“解读”栏只允许写管理行动，不解释检测结果；单个异常菌没有解读。
- 版面分组一处地址不合规就整组作废：肥胖被拆成 6 行，高脂血症出现两次；PDF 路径下检测方的健康关联项目每项重复两行。
- 七维评分在 60 秒内完成归因、审核和修复，两个维度超时无分。

## 现在的流程

入口仍是 `modules/report/evaluation_report.py` 的 `generate_evaluation_report()`。`SHULAN_REPORT_AUTHORING_MODE=chapter`（默认）走下面的流程；设为 `cell` 时走原逐格路径并使用原提示词 `prompts/report/narrative_cell.txt`。

1. **计算指标**（`evaluation_derived_indices.py`）。HOMA-IR、HOMA-β、non-HDL-C、残余胆固醇、TG/HDL-C、FIB-4、BMI 中国分级、腰围判定、代谢综合征组分计数由程序按公式计算，作为普通事实加入记录。每项只在输入齐全且唯一、单位符合时产生；名称带“（计算值）”，来源字段写明公式和所用数值。判读界值不在这里给出。
2. **整理与分组**（原有步骤）。修复了三处会让正确分组整体作废的校验：成员里混入管理目标地址、关注等级写成“高/中/低”、同一成员被后一组重复引用。
   - 未通过独立审核的分组最多修复两轮。修复轮若把遗漏的行归到某个已采纳组（沿用其编号），这些行连同原组作为“扩展”再审一次，通过后才并入（审计键 `templateLayoutExtendedGroups`）。两轮后审核仍认定“是同一问题、没有新增诊断”、只是不认可名称或确定性措辞的分组，成员不再拆散成多行，改用组内首条原始记录的名称和确定性保留为一组；导航、关注等级、检测方关联和行动标签只保留审核认可的部分（审计键 `templateLayoutSourceNamedGroups`）。
   - 未越过判定界值的计算指标（如代谢综合征组分 2/5）只作背景，不进医学评估表；问诊与查体背景记录按正常背景处理，不单列为健康问题。
   - 其余未归组的行按名称字面包含关系并入已有分组。
3. **评分**（`evaluation_template_scores.py`）。规则不变，共享时限由 60 秒放宽到 240 秒；通过审核的扣分构成（各因素分值和资料覆盖状态）写入 `assessmentChart[].explanation`，并给出关注等级标签。
4. **证据召回**（`evaluation_evidence_recall.py`）。文献库（EviMed）、PubMed、联网检索三个来源查询同一批主题，结果进同一个候选池。
   - 临床问题、行为因素先由一次模型调用规划中英文检索式和对象名称（中英文同义词）。
   - 每个异常菌都检索（原来只查前 4 个）；菌群结构的每个指数（GMWI2、F/B、肠型等）各有一个检索问题。
   - 入选是确定性的：文献原文字面出现该对象才建立关联；每个主题按来源类型和年份取前几篇；病例报告、更正、撤稿、会议摘要不入选；标题几乎相同的两篇只取一篇。单句是否真的支持某个结论，由成稿后的整章审核判断。
   - 适用人群按标题判断：儿童、孕产、绝经、老年（受检者未满 60 岁时）以及囊性纤维化、重症、脓毒症、颅脑损伤、透析、器官移植、早产等特定患者人群的文献不用于不属于该人群的受检者；兽医与水产宿主的研究一律不用（基因主题也不例外），实验室啮齿类研究保留并标为 D 级。
5. **按章成稿与审核**（`evaluation_report_writer.py`）。同一张表的格子一批写完，模型拿到完整临床记录、该格对应的检测行（同批各格按轮转分配名额，偏离参考范围的行优先）和候选原文段落；七维评分说明格另拿到各维度分数和影响分数的因素；每格有职责说明和字数范围。随后同一批由审稿任务逐格核对事实、推断、引用和安全性（审稿同样能看到已审过的前文，摘要类格子沿用前文数值不算无据），直接返回改正后的正文；审稿无法改正且属于事实、安全或越界推断问题的格子，带着审稿意见重写一次再审。未通过审核的正文不发布。
   审稿之后每批再做一次文风改写（`humanize_report_chapter`，不开思考）：程序先标出每段的机器写作痕迹（“不是……而是……”、破折号、套话、免责声明、写出来源方、称呼读者、交代信息出处等），只把检出痕迹的格子交给模型改文风，没有痕迹的格子保留审过的原文、不再调用模型。改写段落只有在数值集合不变、“可能/约/阳性/家属”等关键词仍在、没有新增痕迹且不更长时才采用，否则保留审过的原文；改写后的篇幅须在原文的 88%–110% 之间，段首的小标题不得改动。
   文体与写法（`WRITING_GUIDE`）：报告是对外交付的正式书面评估报告，客观陈述、不带人称，不出现“您”，确需指代时写“受检者”；它是通读全部资料后的综合判断，不交代信息出自哪份资料（不写“问卷显示”“体检显示”“菌群检测显示”），同一健康问题的化验、影像、症状、生活方式和肠道菌群依据放在一起分析。各格字数范围保持完整篇幅，不为简短而省略。
   条目式正文：较长的格子按条目书写，每个条目是一个自然段，由小标题和正文组成（成稿结构里是 `title` 与 `text`，发布时写成“小标题：正文”，条目之间空一行）；每格的建议条目见 `_OUTLINES`（如评估意见为“性质与程度／相关结果／临床意义”）。初稿没有分条（整段超过 190 字、缺小标题）时退回重写一次，第二次仍未分条则按原样发布，不因版式丢内容；短格子（要点、菌种、次要发现）仍是一段。
   重点问题管理表的两个短格与对应的随访安排同批书写：`priorityDirections[].basis`（主要依据，带数值的短语）和 `followupAction`（首要措施，固定写成“时限；首要事项；科室；后续复查”四段）。
6. **发布**。沿用 `apply_reviewed_report_blocks`：正文绑定事实编号，引用的原文段落由服务端从原文复制，源数值签名前后一致才发布。
7. **读者措辞**（`evaluation_presentation.py`）。发布前对全部展示字符串做确定性整理：读者只面对一家服务方，不出现检测方、原报告、主检、检测机构、模型等来源方说法，不出现“用户自述，未核验”等采集标记和“不是诊断”“仅供参考”一类免责句（同句里的事实保留）；正文不带人称（“您的甘油三酯”写成“甘油三酯”，介词后和判断句主语处改为“受检者”），去掉交代信息出处的引出语（“问卷显示，”“体检显示”“菌群检测显示”），事实本身保留；常见检验缩写写成中文全称（BMI、HOMA-IR、TSH、LDL-C 等，比值写法如 TG/HDL-C 不动）；统一正文中中文与数字之间的空格，平方单位写成 m²，数值后的中文单位名改为规范符号。数值、单位、参考范围、编码、枚举值和目录固定的章节（附录 A、风险指数分级、关注等级）不改。整理后的数据会按回调契约重新校验，校验不过就整体退回整理前的版本（审计键 `readerWordingError`），措辞整理永远不会让报告交付失败。
8. **读者质量指标**（`reader_quality`，审计键 `readerQuality`）。每份报告记录：来源方说法、采集标记、英文代码的出现次数（应为 0），称呼读者的次数（`secondPerson`，应为 0）、交代信息出处的引出语数量（`sourceLeadIns`）、各类机器写作痕迹的数量，正文总字数、段落长度分布、超过 180 字的段落数（`longParagraphs`）和带小标题的条目数（`titledParagraphs`）。`scripts/check_evaluation_report.py callback.json …` 对任意回调输出同样的指标，出现不应给读者看的内容时返回非零，可用于批量抽检。

成稿顺序：明细行 → 通路联动 → 各章小结 → 总览与结论。后一阶段能看到前面已审过的正文。

## 联网证据通道

- `adapters/report/deepseek_tools.py`：DeepSeek 独立工具接口 `/v1/tools/search`、`/v1/tools/fetch`、`/v1/tools/ocr` 的客户端。408、429、5xx 重试，其余 4xx 不重试。
- `adapters/report/web_evidence.py`：把检索结果转成与文献库相同的 `EvidenceRecord`。原文是检索返回的页面正文片段，记录带完整性校验键，改动后不再被认作原文。题录用 NCBI（PMC 编号）和 Crossref（DOI 或标题）补全。
- `modules/report/web_source_policy.py`：来源准入是白名单——卫生主管部门和学会的指南、同行评议期刊与索引、少数专业参考。科普页、新闻、问答、社交媒体、引文聚合页和镜像站不入选；权威机构站点上只收指南、共识和规范。
- 这是工具 HTTP 接口，不是模型调用。模型调用仍全部经 AION；本适配器与 `EviMedClient`、`PublicEvidenceClient` 属于同一层。AION 0.6.0 内部也调用同一组 Search/Fetch 接口，但只在模型调用内使用且限 5 条、每条 1,200 字符。
- OCR 仅作为扫描件或图片资料的兜底文本来源（`DeepSeekDocumentTextClient`），本地表格解析仍优先。

## 模型与配置

| 配置 | 默认 | 说明 |
|---|---|---|
| `SHULAN_REPORT_AUTHORING_MODE` | `chapter` | `cell` 为原逐格路径 |
| `SHULAN_REPORT_NARRATIVE_THINKING` | `true` | 仅整章成稿和整章审核两类任务开启思考；其余结构化任务不开 |
| `SHULAN_REPORT_NARRATIVE_REASONING_EFFORT` | `high` | `low` / `high` / `max` |
| `SHULAN_REPORT_WEB_EVIDENCE_ENABLED` | `true` | 无工具密钥时自动不启用 |
| `SHULAN_DEEPSEEK_TOOLS_API_KEY` | 空 | 留空且提供商为 deepseek 时复用 `SHULAN_LLM_API_KEY` |
| `SHULAN_REPORT_DOCUMENT_OCR_ENABLED` | `true` | 扫描件 OCR 兜底 |

模型仍由 `SHULAN_LLM_DEFAULT_MODEL` 决定；DeepSeek V4.1 Flash 的模型名是 `deepseek-flash`。思考任务单次超时 420 秒，其余任务 90 秒。

## 回调字段的变化

本节列出的都是已有字段的内容变化，没有新增或删除字段。

字段地址不变，以下原本为空的字段现在有内容，另有一个新增字段：

- `microbiomeAssessment.taxa[].explanation`：偏离参考范围的菌逐项解读（同一菌在多个面板出现时内容相同）。
- `healthOverview.assessmentChart[].assessmentLevel` 与 `explanation`、`diseaseRiskAssessment.overviewMatrix[].attentionLevel`：关注等级和影响分数的因素。
- `diseaseRiskAssessment.riskRanking[]`：菌群风险项目带出风险值，`sourceStatus` 为“菌群评估：<原等级>”，只有关联提示的为“菌群关联”；同一疾病的风险行和关联行合并为一行。
- `medicalAssessment.findings[].value`：整理后的结果文字，每项写成“名称：数值 单位（参考范围；状态）”，便于前端解析成图表；医生原建议不再拼进结果，改由写作任务的 `originalAdvice` 使用；问卷内容合并为“问卷：……”一项。
- `healthOverview.assessmentChart[].explanation`：用文字说明影响分数的因素（如“分数主要受已有的主要健康问题、危险因素影响；部分相关检查缺少。”），不再公开扣分数字。
- 较长的正文字段（`text`、`explanation`、`sourceAdvice`、`association`、`healthMeaning`、`description`）是条目式文本：条目之间以空行分隔，每个条目写成“小标题：正文”。前端可把冒号前的小标题排成行标签，不处理时按段落显示也可读。
- `comprehensiveConclusion.priorityDirections[].basis` 与 `followupAction` 现在有内容：前者是该问题最关键的检查结果（短语），后者是首要措施，格式为“时限；首要事项；科室；后续复查”（全角分号分隔），用于管理一览表和随访日程。
- `appendices.referenceLiterature[].studyType` 有值；新增 `evidenceGrade`（A 指南、共识或系统综述；B 随机对照试验或队列研究；C 综述、其他人体研究或专业参考；D 动物或体外研究）。这是来源类型分级，不是某条建议的证据确定性。文献库渠道标为指南的记录，标题也须像指南（且不是“某指南的影响、比较、依从性”一类研究）才定为 A；标题写明动物或体外研究的一律为 D。

评估报告七章契约（`evaluate.v2.0`）在来源分支上尚未写入 `docs/api/API.md`，本分支也未补写。

## 本地运行

```bash
# 模型、EviMed 等密钥通过进程环境变量提供；脚本不读取私有 .env
python scripts/generate_evaluation_report.py \
    --input request.json \
    --file https://local.invalid/x/report.pdf=/path/report.pdf \
    --output _local_runs/case-01
python scripts/render_evaluation_report.py callback.json report.html
```

`generate_evaluation_report.py` 用内存装配运行与生产相同的 `ReportPipeline`，不需要 Mongo、Redis 和回调地址，输出 `callback.json`、`audit.json` 和 `report.html`。

`render_evaluation_report.py` 是回调的参考呈现（不是接口产物），可供甲方前端对照。它按健康主题而不是按资料来源组织，版式为正式书面报告（章节编号、图表编号、A4 打印分页与页码）：

- **一、评估结论**：四个计数（重点健康问题、超出参考范围的指标、需要关注的领域、未见异常的检查）、总体结论、健康领域评分（雷达图和评分条）、重点健康问题及首要措施表、全部异常指标与参考范围的汇总图。
- **二、分领域评估**：七个健康领域按评分由低到高排列。每个领域先给评分、管理主题和结论，再逐个列出该领域的健康问题；每个问题只出现一次，集中列出检查结果（参考范围图和文字结果）、评估意见、风险评估和管理建议；只与肠道菌群特征相关的疾病方向放在所属领域内，并画出相关菌的丰度。未归入七个领域的发现和未见异常的检查列在其后。
- **三、生活方式与影响因素**：因素、现状、证据强度和可改变程度的一览表，随后逐项分析。
- **四、肠道微生态评估**、**五、营养与代谢功能评估**：指标与参考范围图、菌门构成、各类菌偏离情况、短链脂肪酸、耐药基因表、功能评分和功能通路。
- **六、健康管理方案**：随访与复查日程（按 2 周、1 个月、3 个月、6 个月、12 个月排列）、随访与复查计划表、分项随访安排。
- **附录**：图例与评分说明、名词解释、参考文献。

条目式正文排成“小标题｜正文”的行；没有分条的长段按句分行。参考范围图中区间固定在中段，远超上限时注明“约为上限的 N 倍”，丰度用对数刻度、未检出用空心点。页面静态文字同样不带人称。手机宽度下单列、无横向滚动，表格改为逐行卡片；打印时每章另起一页并带页码。

## 已知限制

- 只在一例真实资料和两例合成资料（女 62 岁多病共存、男 29 岁基本健康）上验证。成稿质量、引用正确率、耗时和费用没有固定病例集的对照数据。
- 同一健康问题的关键数值会在评估意见、风险评估、管理建议和随访安排里各出现一次；各格职责已经分开，但跨格重复没有完全消除。
- 首要措施格式校验（四段）只在初稿时执行一次重写，重写后仍不合格式的按原样发布，参考呈现会尽量按内容识别时限和科室。
- 耗时比原流程长：条目式成稿后，同一例真实资料实跑 4 次为 1174–1215 秒（约 20 分钟），两例合成资料为 1051–1189 秒；此前的整段成稿为 808–997 秒，原流程约 6 分钟。仍在 30 分钟上限内，但余量比之前小；其中检索约 4 分钟，成稿与审核约 14 分钟。三份报告并行生成时单份耗时没有明显变化。
- 参考文献仍会混入少量不理想的条目（例如以指南为题的单中心病例分析、与受检者职业或人群不完全对应的综述）；入选规则是标题级的确定性规则，单句引用是否恰当由整章审核把关。
- 审核是模型审核。它能改掉与记录不符的数值和越界推断，但不能替代医生签发前的人工审阅。
