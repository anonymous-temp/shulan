# Report 主 Agent 与执行版本

Report 模块的数据读取仍由普通业务服务完成。HTTP 报告生成持久受理后，Worker 经 `ReportAgent` 的 `WorkflowAgentPort` 执行既有 Report Pipeline；没有新增路由模型或额外 Prompt。主 Agent 负责固定输入版本、调用域内工作流并核验最终产物的用户、会话和报告身份。

## 当前实现

受理时复制并保存 `report-execution.v1` 清单，包含主 Agent 版本、Report 内容修订、明确的 `report-source-v16` Document 输出、生成时间预算及现有子 Agent 的版本、模型配置和 Prompt 摘要。配置摘要不保存凭据原文。执行前核对完整清单，不把旧任务自动升级到当前实现；同一受理身份重复提交不覆盖原清单。

主 Agent 的命名空间与业务会话隔离。私有 `report.narrative` 和 `report.followup` 继续使用原有 Prompt 和模型调用，工具增强研究循环仍另行交付。主 Agent 注册失败只使本域生成不可用，不关闭共享 Runtime，也不影响已有产物读取。

GutBarrier 通过 Report 的公开持久委派入口提交后续解读。该内部任务也经过同一个 `ReportAgent`，仅生成 `explain_gutBarrier`、`opinion`、`instruction`。独立内部任务 ID 用于存储，回调仍保留来源 `finalReportId/type`；不新增 `evaluate/explain`，不进入普通 Report 列表或 Chat 自动选择范围。

## 迁移与恢复

旧的已开始任务仍按现有中断策略封口，不重新执行模型。旧的已完成产物及回调队列不重新生成，回调持续补投不消耗生成或委派预算。

部署前应先由原版本 Worker 排空尚未开始且没有执行清单的旧队列。此类任务缺少可复现的依赖身份，新 Worker 明确以 `REPORT_EXECUTION_VERSION_UNAVAILABLE` 结束并保存既有失败回调格式，不能伪称具备逐步 checkpoint 恢复，也不能把当前代码标成旧版本继续执行。回退时按任务版本路由；已完成产物不重跑。

本次只完成行为等价主 Agent 接线。Document 快照消费、Profile 独立 renderer、可选 ResearchAgent 和完整循环评测按独立依赖批次推进。

## 验证范围

离线测试覆盖受理拷贝、重复提交固定清单、版本失配拒绝、已开始任务封口、查询绕过 Agent、公开委派保持三类结果及来源 ID，以及模块注册失败隔离。真实模型质量、Mongo 并发和外部回调联调需要独立验收。

参见 [公开委派](report-delegation.md)、[工具执行平台](agent-tool-runtime.md) 和 [目标架构](../docs/architecture/modular-multi-agent-architecture.md)。

## 文档消费执行版本

`report-execution.v2` 在持久受理时固定文档工厂公开的 `document_input_manifest()`：至少包含真实消费者修订，具体实现同时声明输入、输出及兼容发布选择。历史旧工厂明确标识 `report-legacy-documents.v1`；当前默认正式工厂选择 `report-formal-documents.v1` 和 `document-formal-source-v2`，已受理旧任务仍按原清单选择实际旧实现；没有文档源的路径也有独立标识。工厂无版本描述或描述不能稳定保存为 JSON 时，主 Agent 被明确标记为不可用，不使用隐式 latest；若外围持久服务已经受理请求，仍按既有失败产物与交付路径封口，不新增 HTTP 契约。

执行前再次核对工厂版本。进程重启或安装新消费者不会替换已受理清单；不再支持的旧清单以 `REPORT_EXECUTION_VERSION_UNAVAILABLE` 封口，已开始任务仍沿用原中断封口策略，不重跑生成。既有成功产物、查询和持续回调不依赖这次生成版本检查。此改动固定消费者身份，实际材料引用仍由 Document 准备回执和 Report 本域投影固定，不能据此宣称逐步 checkpoint 恢复。

## 评估报告生成调度与性能记录

多章节评估在事实整理、规划及循证库准备完成后，并发执行各正文章节的明细成稿与医学审核。本章明细审核完成即可启动本章汇总；功能通路明细与其他明细并发，汇总仍读取本章已审内容。健康总览和综合结论等待所有正文及汇总完成后再生成，不读取尚未审核的草稿。

同一次评估的章节任务共用六槽模型门禁，仍受叙事适配器的每报告及应用共享限制。章节节点使用独立审计记录，由调度器按目标单元格合并已审检查点；超时、取消及异常先取消并等待全部子任务退出，再进入既有恢复及交付流程。此检查点用于当前进程的中断封口，不新增跨进程自动续写或重新调用模型的承诺。

同章、同依赖范围的相关短汇总可在同一请求中处理，各单元格的地址、长度、事实、引用及审核仍分别校验。仅在原批事实记录、文献和可引用原文片段均完整保留时合并，否则维持原批次。明细和完整问题行保留原分组，既有医学审核、必要重写和按需语言修订继续执行。模型、思考参数、公开字段、章节及 HTML 表格样式不因调度优化而改变。

Web 文献候选按既有排序分批补全，达到原有数量的有效去重结果后停止额外补全，失败与重复条目继续递补；同一论文的并发元数据查询合并并使用有界有效期缓存。检索主题、渠道、原文校验及医学适用性审核保持原规则。

私有生成审计记录章节节点的开始时间及墙钟耗时、批次执行时间、writer 门禁等待及模型调用服务时间。章节之间可重叠，不能把各节点或全部模型调用的耗时相加当作报告总耗时；总耗时仍使用 `stageTimingsMs.total`。这些诊断不进入患者回调或报告正文。真实服务耗时及医学内容一致性须通过相同入参的真实回调和人工逐章对照验收，不能仅由离线测试判断。

审核输入另提供全报告已有条目的名称目录和本格比较范围，用于防止把未在本格展示的项目写成未检测、把局部最值写成全报告最值。名称目录不代表检出或正常，医学结果仍以实际记录及适用文献为准。已完成批次的重大审稿问题按稳定单元格及事实绑定传递给后续写作与审核，本地引用句柄不跨批复用；这些意见不作为新增医学证据。摘要仍核对原值、指南适用前提及阈值用途，不直接把前文当成无条件正确的结论。随访格式仅约束结构，不再包含具体临床处置实例；没有增加整篇报告重写调用或减少原医学审核。
