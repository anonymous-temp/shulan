# 任务指令
你正在编写《肠道屏障报告解读参考手册》的**开场白脚本**与**收尾跟进脚本**。
这两段话分别用在一次解读的最开头和最末尾，解读人会一字不改地念出来。

# 输入数据
【受检者与报告信息】
${meta_json}

【关键数据摘要】
${card_json}

【需要优先跟进的三件事】
${top_three_json}

素材字段说明：
- `meta_json`：受检者姓名、性别、年龄、报告日期、报告名称。
- `card_json`：三项指标的结果评价汇总、IBFC 评分与等级、待明确项与资料缺口的条数。**开场白里不要报具体数值**，只用于把握整体轻重。
- `top_three_json`：程序按「待明确的检测项 + 资料缺口 + 个体临床背景里的异常项」排好序的三件事，收尾脚本必须原样使用，不要增删、不要改写。

# 写法要求

## 开场白（3 分钟以内）
1. **自我介绍**：简短，说明自己是谁、今天做什么。
2. **角色声明**：必须明确说出「我负责帮您看懂这份报告，涉及诊断和用药的问题我会帮您对接医生」这层意思——合规必含项，不得省略、不得弱化。
3. **这份报告是什么**：一句话说清这是肠道屏障功能与相关健康风险的专项评估，**不是体检，也不是疾病诊断**。
4. **流程预告**：分两章讲，大概多久，随时可以打断提问。
5. 开场白里不出现任何具体指标数值、评分或疾病名称，不制造紧张感。

## 收尾脚本（3 分钟以内）
1. **总结三件事**：把 `top_three` 逐条说清楚，并请用户复述确认。
2. **就医或复查确认**：需要补检测或找专科的，确认到具体时间。
3. **随访约定**：约定下一次回访的时间点与方式。
4. **留联系方式**：说明有问题随时可以找谁。
5. 结尾给希望，不催促、不施压、不提任何产品与价格。

# 字数约束
- 开场白四个字段各不超过 80 字。
- 收尾脚本 `summary` 不超过 80 字，`confirm`、`follow_up`、`contact` 各不超过 60 字。
- `three_things` 条数与输入的 `top_three` 完全一致，文字照抄，可在前面加序号。

# 输出格式
请严格遵守以下 JSON Schema（`kind` 字段照抄）：
{
  "opening_script": {
    "kind": "script",
    "self_intro": "自我介绍",
    "role_statement": "角色声明，含对接医生的表述",
    "report_intro": "这份报告是什么、不是什么",
    "agenda": "流程预告"
  },
  "wrap_up_script": {
    "kind": "script",
    "summary": "总结并请用户复述三件事的话术",
    "three_things": ["照抄 top_three 的内容"],
    "confirm": "确认补检测或就医时间的一句话",
    "follow_up": "约定回访的一句话",
    "contact": "留联系方式的一句话"
  }
}
