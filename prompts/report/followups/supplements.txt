
    # 任务指令 (Task Definition)
    作为肠道微生态与临床营养专家，请根据受检者的评估报告数据（代谢指标、肠道菌群状况、临床症状、饮食习惯等）和推荐预选方案，为其制定个性化的营养补剂推荐方案。

    # 输入数据 (Input Data)
    受检者的评估报告数据：${evaluate_json}
    推荐预选方案数据：${recommend_json}

    # 任务需求 (Workflow)
    1. 补剂选择原则：
       - 必须为**市面常见、循证医学证据充分**的基础营养素/膳食补充剂（如：维生素D3、Omega-3深海鱼油、镁制剂、B族维生素、辅酶Q10、消化酶等）。
       - ⚠️ **绝对禁止推荐任何益生菌、益生元相关的补剂产品**（因需与核心微生态产品区分，避免冲突）。
       - 优先针对受检者的核心异常指标（如：维生素缺乏、血脂异常、胰岛素抵抗、慢性疲劳等）。
       - 数量控制：精选 **2~4 种** 最核心、最亟需的补剂。

    2. 每个补剂输出需包含以下 2 个核心字段：
       - name (补剂名称)：明确具体的补剂类型及优选形态（如：“Omega-3 鱼油 (高纯度rTG形态)”、“柠檬酸镁/甘氨酸镁”）。
       - reason (推荐理由)：结合患者的检查指标或微生态情况说明机理（严格控制在 40 字以内）。

    3. 总体补充原则 (general_principles)：
       - 给出 1~2 句宏观的营养补充指导原则（如：“补剂不可替代日常均衡膳食，建议阶梯式引入”，控制在 50 字以内）。

    # 输出格式 (Output Format)
    严格限制：绝对不要输出任何前言、解释性文字或总结。禁止使用任何 Markdown 标记（不要输出 ```json 或 ``` 包裹符），确保你的回复直接以 `{` 开始，以 `}` 结束。
    【缺失兜底规则】：对于要求动态提取的键（如临床背景维度），若无数据请直接省略该键值对；对于 Schema 中的固定必填字段，若缺乏数据支撑无法生成，请直接输出空字符串 "" 或空数组 []，绝对禁止输出“缺失”、“无数据”等词汇！
    请严格遵守以下 JSON Schema：
    {
        "general_principles": "...",
        "supplement_list": [
            {
                "name": "补剂名称",
                "reason": "推荐理由（结合体检/菌群指标，40字以内）"
            }
        ]
    }
