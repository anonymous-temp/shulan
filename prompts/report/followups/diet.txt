
    # 任务指令 (Task Definition)
    作为肠道微生态健康管理专家，请根据受检者的评估报告数据、推荐预选方案，为其制定个性化的临床饮食处方方案。

    # 输入数据 (Input Data)
    受检者的评估报告数据：${evaluate_json}
    推荐预选方案数据：${recommend_json}

    # 任务需求 (Workflow)
    请按顺序执行以下逻辑步骤，并严格映射到 JSON 字段：

    1. 饮食模式 (diet)：优先根据核心疾病标签匹配最适合的饮食模式。如果信息不明确或命中代谢综合征/脂肪肝/血脂异常，请默认推荐【地中海饮食（Mediterranean Diet）】。
       (可选：低GI饮食、低脂饮食、低碳水化合物膳食、江南饮食、DASH饮食、地中海饮食、高蛋白饮食)
       输出格式需包含简要说明，如：“以地中海饮食为基础，提高膳食纤维与植物多样性...”

    2. 餐盘结构 (meals)：输出固定格式的每餐进食比例。
       - 格式要求：`每餐约 [量词]蔬菜 + [量词]蛋白 + [量词]主食`
       - 词汇红线：绝对禁止使用"克(g)"、"毫升(ml)"等绝对计量单位。只能使用视觉化量词（如："1/2"、"1/4"、"1掌心"、"2拳头"、"半碗"等）。

    3. 核心膳食原则 (根据体征与产品示例，分别输出以下 5 项，每项严格控制在 30 字以内)：
       - 膳食纤维 (fiber_advice)：给出每日目标及递增原则（如：目标30-35g/日，从当前耐受量逐步增加）。
       - 脂肪来源 (fat_advice)：明确应减少的坏脂肪和应优先的好脂肪（如：减少油炸及反复加热油；优先橄榄油、深海鱼）。
       - 碳水来源 (carb_advice)：明确限制的高糖食物及主食搭配建议。
       - 植物多样性 (plant_diversity)：给出跨类别的食物多样性指导。
       - 腹胀管理 (bloating_management)：针对纤维摄入增加可能引起的腹胀给出实操建议（如：胀气明显时先减量再缓慢递增）。

    4. 饮食监测要求 (diet_monitoring)：根据用户的健康状态，给出具体的饮食记录和监测建议（控制在 50 字以内）。

    5. 每日营养目标 (target)：基于用户的体检信息（身高体重、疾病、体成分需求）科学估算以下7个每日摄入目标（仅输出数值及单位的字符串，如 "1500-1800 kcal"）。
       包含：能量(energy_kcal)、蛋白质(protein_g)、脂肪(fat_g)、碳水化合物(carbs_g)、膳食纤维(fiber_g)、钠摄入(sodium_mg)、碘摄入(iodine_ug)。

    6. 食物选择与一日执行 (food_execution)：根据患者情况，提供具体的食物选择红绿灯及一日三餐执行指引。共10个小模块，【严格限制】每个小模块的文字均不要超过 30 字。
       - 优先选择 (priority_choices)：如燕麦、全谷、杂豆、深色蔬菜、菌菇、坚果、深海鱼、低糖水果等。
       - 适量摄入 (moderate_intake)：如瘦肉、鸡蛋、无糖乳制品、豆制品、橄榄油等。
       - 减少摄入 (reduce_intake)：如油炸食品、肥肉、精制甜点、含糖饮料、高盐加工食品等。
       - 腹胀期调整 (bloating_adjustment)：洋葱、豆类、菊粉类食物若明显加重胀气，可减少单次量后再递增等建议。
       - 早餐 (breakfast)：早餐的具体搭配建议（如：燕麦/全麦主食+鸡蛋或无糖乳制品+一份水果）。
       - 午餐 (lunch)：午餐的具体搭配建议（如：半盘蔬菜+鱼/禽/瘦肉或豆制品+粗杂粮主食）。
       - 晚餐 (dinner)：晚餐的具体搭配建议（如：减少油腻，优先清蒸水煮，主食量适中）。
       - 加餐 (snack)：加餐建议（如：坚果、无糖酸奶或低糖水果）。
       - 饮水 (hydration)：日常饮水要求（如：分次足量饮水，避免含糖饮料）。
       - 记录 (record)：记录建议（如：记录三餐、腹胀与排便变化，便于阶段复盘）。

    # 输出格式 (Output Format)
    严格限制：绝对不要输出任何前言、解释性文字或总结。禁止使用任何 Markdown 标记（不要输出 ```json 或 ``` 包裹符），确保你的回复直接以 `{` 开始，以 `}` 结束。
    【缺失兜底规则】：对于要求动态提取的键（如临床背景维度），若无数据请直接省略该键值对；对于 Schema 中的固定必填字段，若缺乏数据支撑无法生成，请直接输出空字符串 "" 或空数组 []，绝对禁止输出“缺失”、“无数据”等词汇！
