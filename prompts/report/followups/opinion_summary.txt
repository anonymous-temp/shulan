# 任务指令
根据以下评估报告生成诊断意见摘要，并列出实际引用的文献 ID。只使用可核对的受检者事实。

# 输入数据
${evaluate_json}

# 分析要求
1. conclusion：概括实际支持的主要结果，100字以内。逐项核对菌群失衡、肠道炎症相关信号、糖脂代谢相关特征及维生素合成潜能是否有原始依据；只描述有依据的维度，不把未测项目写成正常，也不把功能潜能等同临床营养缺乏。
2. 无菌群依据时，可概括实际提供的常规检验、影像、检查所见、症状、病史及可比时间趋势，不暗示已完成菌群检测或自动建立肠道病因。若仅有正常检查，结论限定在实际项目和日期范围；若只有身份信息，conclusion 返回 null 或简短的“本项评估结果暂缺”。
3. clinical_context：保留固定子字段“临床定位”，没有可支持的定位时返回 null。其他动态维度仅在实际输入支持时添加，每项20字以内；“临床定位”100字以内，说明已有结果及其适用范围，不强行指定微生态干预为核心病因治疗。
4. risk：只有存在可核实且适用于当前评估目标的分级依据时，才返回“低风险”“中等风险”或“高风险”；缺乏依据返回 null。无阳性记录、单项正常或只有身份信息均不能默认整体低风险。
5. evidence_refs：仅填写实际引用且可核对的 ID，无引用时返回 []。不得添加虚构文献或用证据标题替代受检者结果。

# 输出约定
只返回 JSON，不附 Markdown、前言或额外解释。固定字段名称全部保留；缺失标量返回 null，数组返回 []，声明了子字段的对象保留对应子字段。不得要求缺少依据时仍补造非空结论或分级。
以下为无有效评估依据时的结构示例；有依据时在同名字段填入真实内容，动态临床维度仅按已有资料增补：
{
  "conclusion": null,
  "clinical_context": {
    "临床定位": null
  },
  "risk": null,
  "evidence_refs": []
}
