# 任务指令
你正在编写《用户报告解读参考手册》的**开场白脚本**与**收尾跟进脚本**。
这两段话分别用在一次解读的最开头和最末尾，解读人会一字不改地念出来。

# 输入数据
【受检者与报告信息】
${meta_json}

【关键数据速查卡摘要】
${card_json}

【需要优先关注的三件事】
${top_three_json}

素材字段说明：
- `meta_json`：受检者姓名、性别、年龄、报告日期。
- `card_json`：综合评分与等级、六维分数、异常指标与影像检查的条数统计。开场白里**不要报具体指标数值**，只用于把握整体轻重。
- `top_three_json`：本次需要优先关注的事项，最多三件，已按优先级排好序。收尾脚本原样使用已有事项，不要增删、不要改写问题名；为空时 `three_things` 返回 []。

# 写法要求

## 开场白（3 分钟以内）
1. **自我介绍**：简短，说明自己是谁、今天做什么。
2. **角色声明**：必须明确说出"我负责帮您看懂这份报告，涉及诊断和用药的问题我会帮您对接医生"这层意思——这是合规必含项，不得省略、不得弱化。
3. **流程预告**：告诉用户接下来分几步讲、大概多久、随时可以打断提问。
4. 语气温和、不铺垫风险、不制造紧张感。开场白里不出现任何具体的异常指标或疾病名称。

## 收尾脚本（3 分钟以内）
1. **总结三件事**：把 `top_three` 逐条说清楚，并请用户复述确认。
2. **就医确认**：仅在报告已有就医或复查建议时，请用户确认安排；没有时不暗示已有就医事项。
3. **随访约定**：只复述已有的回访时间点与方式；没有明确安排时说明后续再确认，不自行给出时间。
4. **留联系方式**：仅使用输入已有的对接人和联系方式；未知时不编造姓名、电话或可用渠道。
5. 结尾给希望，不催促、不施压、不提产品价格。

# 字数约束
- 开场白三个字段各不超过 80 字。
- 收尾脚本 `summary` 不超过 80 字，`follow_up` 与 `confirm` 各不超过 60 字。
- `three_things` 条数与输入的 `top_three` 完全一致，文字照抄问题名，可在前面加序号。

# 输出格式
请严格遵守以下 JSON Schema（`kind` 字段照抄）：
{
  "opening_script": {
    "kind": "script",
    "self_intro": "自我介绍",
    "role_statement": "角色声明，含对接医生的表述",
    "agenda": "流程预告"
  },
  "wrap_up_script": {
    "kind": "script",
    "summary": "总结并请用户复述三件事的话术",
    "three_things": ["照抄 top_three 的三条"],
    "confirm": "确认就医时间的一句话",
    "follow_up": "约定回访的一句话",
    "contact": "留联系方式的一句话"
  }
}
