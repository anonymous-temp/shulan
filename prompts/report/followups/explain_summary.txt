# 任务指令
根据以下评估报告生成专业、简洁的结果解读摘要，并标记实际引用的文献 ID。

# 输入数据
${evaluate_json}

# 分析要求
1. title：40字以内，概括实际有依据的主要结果或待补充状态；缺乏依据时返回 null 或“评估结果待补充”。不根据空数据判断是否需要住院或急诊。
2. conclusion：100字以内，分别核对菌群失衡、肠道炎症相关信号、糖脂代谢相关特征、维生素合成潜能是否有真实依据，仅描述实际支持的维度及范围。不以机制关联替代个体结果，不把预测潜能等同已确诊疾病或营养缺乏。
3. 没有菌群依据时，仍可使用实际提供的常规检验、影像、检查所见、病史与症状；可比的连续结果可描述变化趋势。不得暗示已做菌群测序，不能把已有非菌群结果自动解释为菌群失衡或屏障受损。
4. 真实正常结果只描述具体检查项目及其日期范围，不代表整体正常或整体低风险。若只有身份信息，conclusion 返回 null 或简短的“本项评估结果暂缺”，不补造稳态或无异常结论。
5. risk：仅在输入有可核实且适用于当前评估目标的分级依据时返回“低风险”“中等风险”或“高风险”；缺少依据时返回 null，不因没有阳性发现而默认最低风险。
6. evidence_refs：仅保留实际引用且可核对的文献 ID；无可用引用时返回 []。

# 输出约定
只返回 JSON，不附 Markdown、前言或额外解释。固定字段名称全部保留；缺失标量返回 null，数组返回 []，不通过非空要求迫使生成无依据内容。
以下为无有效评估依据时的结构示例；有依据时在同名字段填入真实内容：
{
  "title": null,
  "conclusion": null,
  "risk": null,
  "evidence_refs": []
}
