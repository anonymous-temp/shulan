
    # 任务指令 (Task Definition)
    作为临床医生，请根据受检者评估报告中的源事实，判断受检者的就医紧迫程度，并给出措辞与紧迫程度相匹配的就医提示。

    # 输入数据 (Input Data)
    受检者的评估报告数据：${evaluate_json}

    # 分级规则（只能三选一）
    1. urgent（尽快就医）：存在需要尽快医疗干预的情况。
       - 报警症状：便血或黑便、持续或剧烈腹痛、不明原因体重明显下降、持续发热、吞咽困难、长期腹泻伴消瘦等；
       - 检验指标严重偏离参考范围（如血红蛋白明显降低、血糖/肝肾功能严重异常、肿瘤标志物明显升高、便潜血阳性）；
       - 影像或检查结论明确提示需要尽快处理（如明确的恶性征象、急性病变）；
       - 评估报告中明确写有“尽快就医”“立即就诊”等结论。
    2. follow_up（近期复查）：存在需要进一步检查明确、但无需紧急处理的情况。
       - 需要专科随访明确性质的影像发现（如结节、囊肿、结石、息肉等，且无急性表现）；
       - 粪便测序检出的病原体或条件致病菌序列（尤其是低丰度序列），不等同于感染，需要检查排除；
       - 轻中度偏离参考范围、需要复查确认的检验指标；
       - 菌群评估提示的疾病风险（如“2型糖尿病高风险”）不单独构成 follow_up，除非有对应检验指标异常。
    3. none（暂无需就医）：没有上述情况。

    # 写法要求
    1. 只能依据输入数据中**确实出现**的内容判断与书写，严禁虚构指标或症状；拿不准时选择较低的一级，不得夸大。
    2. urgent：content 写明具体异常 + 建议就诊科室 + “建议尽快到医疗机构进一步诊断和治疗”，不超过 60 个汉字。
    3. follow_up：content 写明需要明确的发现 + 建议复查的科室或检查项目，语气平和，使用“建议近期复查/进一步检查明确”，**不得**使用“尽快就医”“诊断和治疗”等措辞；病原体序列写成“需检查排除”，不得写成感染。不超过 60 个汉字。
    4. none：content 输出一句通用就医提醒即可。

    # 输出格式 (Output Format)
    严格限制：绝对不要输出任何前言、解释性文字或总结。禁止使用任何 Markdown 标记（不要输出 ```json 或 ``` 包裹符），确保你的回复直接以 `{` 开始，以 `}` 结束。
    请严格遵守以下 JSON Schema（示例内容仅供参考格式，不可照抄）：
    {
        "level": "follow_up",
        "content": "腹部CT示结肠肝曲结节，建议近期到消化内科复查明确性质；粪便检出结核分枝杆菌序列，建议行结核感染T细胞检测排除。"
    }
