
    # 任务指令 (Task Definition)
    根据下方提供的评估报告数据，完成结构化信息提取与分析任务。

    # 输入数据 (Input Data)
    受检者的评估报告 JSON 数据如下：
    ${evaluate_json}

    # 原报告参考原文（程序从原报告中提取；为“（无）”表示原报告没有这一段）
    【综合评估参考】${body_mass_source}
    【健康风险参考】${risk_warning_source}

    # 任务需求 (Workflow)
    请按顺序执行以下逻辑步骤，并将结果映射到最终的 JSON 格式中：
    1. 肠型提取 (intestine_type)：直接从报告 JSON 中提取受检者的肠型分型结果。
    2. 优势菌种识别 (best_bacteria)：从数据中提取丰度最高、最具代表性或报告中明确指出的核心有益菌（最优菌种）名称。
    3. 失衡等级判定 (unbalance_type)：基于报告中菌群种类、数量、比例及移位情况的变化，将失衡等级严格判定为以下三项之一：
       - 一度失衡（潜伏型微生态失衡）：亚健康人群为主。表现为定量检查上的菌群组成变化，临床无或仅有轻微表现。属可逆性改变（可通过调节生活方式自行恢复）。
       - 二度失衡（局限微生态失衡）：老年、慢病或慢病前期人群为主。出现多种慢性疾病表现（如慢性肠炎、内毒素LPS入血等）。不可自行恢复，需干预修复。
       - 三度失衡（菌群交替症或二重感染）：重疾人群为主。原籍菌被严重抑制，非正常菌群或条件致病菌异常增殖占据优势。宿主微生态稳态彻底改变，需临床治疗。
    4. 综合评估 (body_mass)：本报告是对原报告的解读，这一段要和原报告对得上，精简为主。
       - 有【综合评估参考】时：以它为蓝本精简改写成 1–2 句、不超过 100 字。保留原文的主要结论（原文有评分 / 分级就照写、本次主要变化、整体判断与后续方向），关键用词与原文保持一致；不新增原文没有的指标、数值和结论，不逐项罗列指标，原文里的就医 / 转诊类句子不要保留。
       - 参考为“（无）”时：用 1–2 句、不超过 100 字概括本次主要检测发现与整体状态，只点出最主要的 1–2 项变化，不罗列指标数值。
       - 指标异常一律写成“××指标异常”（如“伴二胺氧化酶（DAO）指标异常”“hs-CRP指标异常”），不写“异常升高”“轻度 / 中度 / 显著升高”“偏高”等程度描述，即使原文这样写也要改；未升高的指标照原文写“未同步升高”等。
    5. 健康风险提示 (risk_warning)：同样以原报告为准，精简为主。
       - 有【健康风险参考】时：以它为蓝本精简成 1–2 句、不超过 80 字，只写本次主要变化与复核重点，关键用词与原文保持一致；去掉检查日期、风险项计数（如“低风险22项、中风险4项”）、“本章按8个系统逐项复核”这类过程性描述；不新增原文没有的内容。
       - 参考为“（无）”时：用 1 句、不超过 60 字概括本次最主要的异常发现，依据检验指标异常、影像阳性发现与主诉症状，菌群结果仅作补充。
       - 指标异常一律写成“××指标异常”（如“hs-CRP指标异常”），不写“异常升高”“轻度 / 中度 / 显著升高”“偏高”等程度描述，即使原文这样写也要改。
       - 不要写具体的疾病风险名单、“××慢病风险较高”或“肠道屏障受损 / 内毒素入血 / 慢性低度炎症”这类机制说明：程序会在你写的内容后面按固定句式接上机制说明和风险最高的 2–3 个慢病。
       - 通用要求：菌群报告预测的疾病风险须写成“菌群评估提示……风险”，不得写成已存在的疾病；粪便测序检出的致病菌序列只能表述为“需进一步检查明确”，不得写成感染结论。本内容属于医生出具的处方与医嘱，**不得**出现“建议就医”“及时就诊”“到医疗机构进一步诊断和治疗”“按医嘱随访”等转诊类表述。有风险内容时，结尾不要追加“维持膳食均衡、规律作息与适度运动”之类的生活方式建议。
       严禁出现“现有评估资料”“现有资料 / 现有数据”“资料有限”“根据提供的数据”等描述数据多少的话术。输入数据缺少可判断风险的依据时，直接写维持性健康建议（如：维持膳食结构均衡、规律作息与适度运动，注重肠道微生态的长期稳态维护），不要写“未提示明确风险”“风险分级属最低档”之类的说明；程序会在末尾自动追加上传更多报告的引导语，不要自己写。
    6. 参考文献溯源 (evidence_refs)：核查上述分析引用的证据数据，提取对应的参考文献 ID 数组。

    # 输出格式 (Output Format)
    严格限制：绝对不要输出任何前言、解释性文字或总结。禁止使用任何 Markdown 标记（不要输出 ```json 或 ``` 包裹符），确保你的回复直接以 `{` 开始，以 `}` 结束。
    【缺失兜底规则】：对于要求动态提取的键（如临床背景维度），若无数据请直接省略该键值对；对于 Schema 中的固定必填字段，若缺乏数据支撑无法生成，请直接输出空字符串 "" 或空数组 []，绝对禁止输出“缺失”、“无数据”等词汇！

      "unbalance_type": "...",
      "body_mass": "...",
      "risk_warning": "...",

    }
