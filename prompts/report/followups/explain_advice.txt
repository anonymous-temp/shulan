
    # 任务指令 (Task Definition)
    请深度阅读下方提供的受检者肠道菌群报告“诊断依据(包含异常情况及导致原因)”数据。
    针对里面提到的每一项异常以及它的**导致原因 (causes)**，生成涵盖多个维度的健康指导与行动建议。建议必须**直接对症**解决提到的“不良习惯或生理原因”，并包含预防未来恶化的指导。

    # 输入数据 (Input Data - 诊断依据与异常问题)
    【本次重点评估的异常问题 (problem) 集合】：
    ${advice_context_json}
    【受检者完整报告 JSON 数据】：
    ${evaluate_json}

    # 模块定义 (Modules)
    1. report_interpretation (报告整体理解)：即“肠道菌群报告应该怎么放进整体健康里理解”。**必须严格输出3段话（生成3个字符串），每段话绝对不能超过100字**：
       - 第一段（定性与干预原则）：说明菌群失衡及相关功能减弱，结合现有的代谢问题（如肥胖、脂肪肝等），核心意义是提示调整饮食与生活方式，而非确诊具体疾病。
       - 第二段（致病菌信号解读）：说明检出极低丰度的高危致病菌DNA信号不等于活菌感染，若无相关临床症状，严禁盲目恐慌或滥用抗菌药物。
       - 第三段（营养潜能与补充标准）：说明报告提示的“维生素等合成潜能低”不代表机体实质性缺乏，营养剂的补充必须结合临床化验和实际症状，不可仅凭报告盲目长期服用。  

    2. Plan (时间计划表)：结合报告中的异常问题 (problem)，为受检者制定分阶段的健康管理行动计划。要求动作明确、贴合实际症状与微生态干预逻辑，且必须包含四个固定阶段："未来1-2周"、"未来1个月"、"未来2-3个月"、"未来6-12个月"。

    3. daily_execution (日常执行方案)：必须严格针对【吃饭】、【运动】、【睡眠】、【烟酒和压力】四个方面，给出极具实操性的干预建议。
       - 格式：输出为一个包含4个固定键值对的 JSON 对象 (Object)。严格使用 "吃饭"、"运动"、"睡眠"、"烟酒和压力" 作为键名 (key)。
       - 字数约束：每个键对应的内容 (value) 必须严格控制在100字以内。

    4. medical_alerts (出现这些情况请及时就医)：根据传入的异常问题 (problem) 进行临床预判，评估这些菌群失衡或病理趋势若持续恶化，可能会引发哪些严重的实质性症状（如不明原因消瘦、持续腹痛、便血等），并给出明确的专科就诊建议。
       - 格式：输出为列表形式。

    # 输出格式 (Output Format)
    严格限制：绝对不要输出任何前言、解释性文字或总结。禁止使用任何 Markdown 标记（不要输出 ```json 或 ``` 包裹符），确保你的回复直接以 `{` 开始，以 `}` 结束。
    【缺失兜底规则】：对于要求动态提取的键（如临床背景维度），若无数据请直接省略该键值对；对于 Schema 中的固定必填字段，若缺乏数据支撑无法生成，请直接输出空字符串 "" 或空数组 []，绝对禁止输出“缺失”、“无数据”等词汇！
