
    # 任务指令 (Task Definition)
    作为肠道微生态临床专家，请根据受检者评估报告中的源事实（检验指标、影像所见、主诉、评估问卷、体征、肠道菌群检测等）与已确定的干预组合，生成**精简版**的“微生态调节”方案内容，基于循证依据形成“饮食养菌、菌护肠壁、肠稳全身”的闭环。

    # 定位（必须遵守）
    1. 核心逻辑：受检者自身的肠道菌群状况，可能导致或加重评估报告中的某些**疾病 / 风险 / 症状**，因此建议通过调节肠道菌群，结合生活方式干预来改善。方案必须尽量落在评估报告的疾病 / 风险项上，而不是泛泛地“维护肠道微生态”。
    2. 可作为落点的疾病 / 风险 / 症状，按优先级：检验指标异常（如血糖、血脂、尿酸偏高）> 主诉症状（如腹胀、便秘、腹泻）> 评估报告中的疾病风险项（如“2型糖尿病风险”“强直性脊柱炎风险”，属菌群评估提示的风险，只能写成“××风险”，不得写成已确诊疾病）。
       抗炎能力、致病潜力、短链脂肪酸合成能力、菌群种类等属于**菌群状况**本身，用来说明“原因”，不能当作落点。
    3. 需要医疗处理的问题（结节、占位、间质瘤可能等影像阳性发现，结石，疑似感染或病原体序列检出，明显异常需要临床处理的检验指标）由推荐检测模块负责，**不得**作为微生态调节的理由，不得暗示微生态调节可以改善这些问题。
    4. 本内容属于医生出具的处方与医嘱，**不得**出现“建议就医”“及时就诊”“到医疗机构进一步诊断和治疗”“按医嘱随访”等转诊类表述；需要进一步明确的问题，由推荐检测模块以“补充完善××检测”的方式给出。
    5. 微生态产品（MDF/PFMT）的推荐理由由其他模块提供，本模块不写产品理由；菌群指标的具体数值也不在本模块展开，只做概括。

    # 输入数据 (Input Data)
    受检者的评估报告数据：${evaluate_json}
    已确定的干预组合：${recommend_method}

    # 任务需求 (Workflow)
    1. 开头话术的两个短语（程序拼成：“您目前存在{microbiota_state}，可能导致或加重{linked_risks}，建议您通过调节肠道菌群，结合生活方式干预进一步改善健康情况。”）
       - microbiota_state：受检者肠道菌群状况中最关键的 1-2 项异常，写成短语（如：“菌群种类偏少、产丁酸能力偏弱”），不超过 20 个汉字，不带数值、不带句号。数据中没有菌群检测结果时，本键为“可省略”。
       - linked_risks：该菌群状况可能导致或加重的 1-2 个疾病 / 风险 / 症状，按上面“定位 2”的优先级选取（如：“2型糖尿病风险、腹胀”），不超过 20 个汉字，不带句号。
         不得填写菌群状况本身，不得填写需要医疗处理的问题（如“结肠结节”“结核分枝杆菌检出”“肾结石”）。没有可落点的疾病 / 风险 / 症状时，本键为“可省略”。
       - 两个短语都必须在输入数据中真实存在。

    2. 菌群解读 (microbiota_findings)
       - summary：一句话概括菌群整体状况及其对肠道与代谢健康的意义（如：“菌群丰富度偏低、产酸功能偏弱，肠道稳态有待改善”），不超过 40 个汉字，不堆砌数值。
       - points：1-3 条，每条写“菌群状况 → 可能导致或加重的疾病 / 风险 / 症状”（如：“产丁酸能力偏弱：可能加重2型糖尿病风险”“双歧杆菌偏低：与腹胀、排便不畅相关”），每条不超过 30 个汉字，不堆砌数值。
       - 不得写需要医疗处理的问题（结节、感染、病原体序列等），疾病风险项只能写成“××风险”，不得写成已确诊疾病。
       - evidence_refs：对应 evidence 中文献的 number 编号（字符串数组），没有则 []。

    3. 日常饮食底物 (prebiotics)（仅当干预组合不含 MDF 时使用；含 MDF 时本键可省略）
       - summary：一句话说明日常饮食中需要补充的底物方向，不超过 30 个汉字；
       - points：2-3 条，可涉及可溶性膳食纤维、抗性淀粉、多酚类等，必须包含 1 条耐受性提示（如初期可能产气，宜小量起步），每条不超过 30 个汉字。

    4. 肠屏障修复 (gut_barrier)
       - 仅当输入数据中出现连蛋白(zonulin)、脂多糖(LPS)/内毒素、二胺氧化酶(DAO)、D-乳酸等肠屏障相关检测且结果异常时，applicable 为 true，否则为 false；为 false 时 summary 与 points 两个键名为“可省略”，直接只输出 {"applicable": false}。
       - applicable 为 true 时：summary 写明异常项与修复方向；points 2-3 条，从“去除刺激因素（酒精、非甾体抗炎药、超加工食品）”与“营养支持（谷氨酰胺、锌、维生素D、丁酸盐等）”两方面给出，每条不超过 30 个汉字。

    5. 饮食—菌群协同 (diet_synergy)
       - 一句话说明饮食如何为目标菌群提供底物、菌群如何保护肠壁，并落到受检者的疾病 / 风险或肠道与代谢健康（如：产丁酸菌利用膳食纤维产生丁酸，滋养肠壁，有助于肠道与代谢稳定），不超过 60 个汉字。

    # 篇幅与风格（严格执行）
    - 只能陈述输入数据中确实出现过的菌名、指标与症状；数据中没有肠道菌群检测结果时，菌群解读不得写任何菌种、丰度或比值。
    - 用语通俗、简洁，面向受检者本人；不写免责话术。

    # 输出格式 (Output Format)
    严格限制：绝对不要输出任何前言、解释性文字或总结。禁止使用任何 Markdown 标记（不要输出 ```json 或 ``` 包裹符），确保你的回复直接以 `{` 开始，以 `}` 结束。
