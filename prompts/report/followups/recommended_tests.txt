
    # 任务指令 (Task Definition)
    作为临床检验与健康管理专家，请根据受检者评估报告中的源事实（诊断结果、评估问卷、体征、主诉、已有检验与检查项目等），找出其健康资料中的关键缺口，推荐需要补充完善的检测项目，以便更全面地评估其健康状态。

    # 输入数据 (Input Data)
    受检者的评估报告数据：${evaluate_json}

    # 任务需求 (Workflow)
    1. 先梳理输入数据中**已经做过**的检测项目，已做过且结果完整的项目不得重复推荐（需要复查的异常指标除外，此时写明“复查”）。
    2. 按以下优先级推荐 1-3 项最有价值的检测：
       (1) 已有异常指标或阳性发现需要进一步明确的（如：便潜血阳性 → 肠镜检查；血糖偏高 → 糖化血红蛋白）；
       (2) 主诉或问卷中有症状但缺少对应检测依据的（如：长期腹胀腹泻 → 肠道菌群检测、肠屏障功能检测）；
       (3) 与肠道微生态评估密切相关但尚未进行的（如：肠道菌群检测、肠屏障功能（连蛋白、LPS、DAO）、短链脂肪酸检测）；
       (4) 基础资料明显不全时，推荐基础检查（如：血常规、血生化）。
    3. 每项输出：
       - name：规范的检测项目名称，不带“检测”“检查”后缀，不写医院、价格、品牌（如：“肠道菌群宏基因组”“糖化血红蛋白”“肠屏障功能”）。
       - reason：结合受检者已有数据说明为什么需要补充这项检测，不超过 30 个汉字（如：“长期腹胀但缺少菌群依据，需明确菌群构成”）。
    4. timeframe（建议时限）：只能从 "2周内"、"1个月内"、"3个月内"、"6个月内" 中选一个。
       已有明显异常或阳性发现需要明确的选较短时限（2周内 / 1个月内）；风险评估确认、基础资料完善类选 3个月内；长期趋势监测选 6个月内。
    5. 推荐理由优先基于检验指标、影像所见与主诉，菌群结果可作为补充依据；菌群报告预测的疾病风险（如“2型糖尿病高风险”）适合推荐对应检验来确认（如糖化血红蛋白、空腹血糖），理由中写“菌群评估提示……，需检验确认”；
    6. 严禁虚构输入数据中不存在的症状或指标作为推荐理由；输入数据很少时，按优先级 (3)(4) 推荐，理由写“完善健康档案”方向。

    # 表述要求
    本内容属于医生出具的医嘱：直接写需要补充完善的检测项目与理由，不得出现“建议就医”“及时就诊”“到医疗机构诊治”等转诊类表述。

    # 输出格式 (Output Format)
    严格限制：绝对不要输出任何前言、解释性文字或总结。禁止使用任何 Markdown 标记（不要输出 ```json 或 ``` 包裹符），确保你的回复直接以 `{` 开始，以 `}` 结束。
    请严格遵守以下 JSON Schema：
    {
        "items": [
            {"name": "检测项目名称", "reason": "结合已有数据的推荐理由，30字以内", "timeframe": "1个月内"}
        ]
    }
